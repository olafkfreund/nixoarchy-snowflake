# Plan: CI for nixoarchy-snowflake

## Summary of the approved spec

**The probe:** a throwaway workflow on `ci-probe/63` measured `ubuntu-latest` (4 vCPU).
- The sandbox tests run after two changes on the runner: `kernel.apparmor_restrict_unprivileged_userns=0`, and Nix's
  `env` bind-mounted over `/usr/bin/env`.
- The whole suite, file by file: 43 min.
- 83 of 89 files passed.

**What CI is:**
- **Two jobs side by side** (owner decision, 2026-11-14):
  - `test` (40 min limit): the package build, `nix flake check`, and every test file except the two slowest
  - `fit-slow` (75 min limit): `test_character_fit` and `test_accessories_fit`, each with a 1800 s deadline
- **A runner script** that:
  - runs each test file in its own process, with a deadline, a fresh `HOME` and `XDG_RUNTIME_DIR`, and process cleanup
  - fails on a timeout, a failure, a missing report, no tests, or a skip that isn't on a reviewed allow-list with a
    reason
- **Tools come from a `ci` dev shell** on the locked flake, never the registry or Ubuntu.

**Fixes the probe found:**
- `test_sessions` read a live herdr pane
- `test_mail` depended on host audio
- `mirror_fit` used a fixed wait
- the character halo overflows with DejaVu fonts: issue #87, fixed in the app on its own branch, **before this PR
  merges**. The test bound isn't loosened, and CI doesn't switch fonts.

4. **`.github/workflows/ci.yml` (new):** as in spec section 4:
   - `name: ci`
   - `on: push: branches: [main]`, `pull_request`, `workflow_dispatch`
   - `permissions: contents: read`
   - `concurrency: {group: "ci-${{ github.event.pull_request.number || github.sha }}", cancel-in-progress: true}`
   - Both jobs: `runs-on: ubuntu-latest`. Their steps:
     1. `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (`# v7.0.1`), with `fetch-depth: 0` and
        `persist-credentials: false`
     2. `cachix/install-nix-action@526118121621777ccd86f79b04685a9319637641` (`# v31.3.0`)
     3. one setup step:

        ```bash
        # GitHub runner only: let bwrap make user namespaces, and give the sandbox a Nix env, as on NixOS.
        sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
        sudo mount --bind "$(nix develop .#ci -c sh -c 'command -v env')" /usr/bin/env
        git rev-parse --verify origin/main   # the character baseline needs it; fail here, not as a skip later
        ```

   - **`test`** (`timeout-minutes: 40`): after the setup, these steps:
     1. `nix build -L .#packages.x86_64-linux.default`
     2. `nix flake check -L`
     3. `nix develop .#ci -c python3 -B .github/ci/run_tests.py --exclude test_character_fit.py --exclude
        test_accessories_fit.py`
   - **`fit-slow`** (`timeout-minutes: 75`): after the setup, one step:
     `nix develop .#ci -c python3 -B .github/ci/run_tests.py --deadline 1800 test_character_fit.py
     test_accessories_fit.py`

   Use exactly the two SHAs above. They match nixi-nixarchy's CI, as checked on 2026-11-14.

   **The setup step:** put the `env` path in a variable on its own line, `env_bin="$(nix develop .#ci -c sh -c
   'command -v env')"`, then `sudo mount --bind "$env_bin" /usr/bin/env`. That way a failing `nix develop` fails the
   step itself, instead of being hidden inside `sudo`'s arguments.

   Each `run_tests.py` command goes on **one line** in the YAML. They are wrapped above only for reading.
   → verify:
   - `nix run nixpkgs#actionlint -- .github/workflows/ci.yml` is clean. That one tool may come from the registry: it
     only runs locally, never in CI.
   - The real check is the PR run (see Tests).

   Traps:
   - Never put secrets or `${{ github.event.* }}` text into `run:` lines.
   - Keep the `git rev-parse` line: it turns a shallow checkout into a failure instead of a skip.
