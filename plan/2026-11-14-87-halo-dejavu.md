# Plan: the halo stays inside its margin at the top of its float

## Summary of the approved spec

- **The cause:** the halo floats by `translate(0, sin(t·1.6)·2.2)` (`app/static/index.html:2432`). At the top of
  that float, the plugin character's halo reaches 2.80 px on p620 with either font, past the 3 px margin. Devil and
  Terminal have only 0.03–0.04 px left there.
- **The font is ruled out:** a DejaVu-only fontconfig moves the top by 0.05 px. p620's page actually renders in
  Liberation Sans.
- **The fix (approved: `cy -113`):** draw the halo 1 unit lower, about 1.1 px. Measured with the float pinned at the
  top:
  - plug:fixture: 3.88–4.00
  - devil: 4.22–4.87
  - terminal: 3.97

  The estimated true worst is about 3.2 px, because the bounce and the roll are still sampled.
- **The check pins the float at its top** through a wrapper, with a guard that fails if the pin stops working. The
  fit bound doesn't change.
- **Not changed:** other skins, CI, fonts, and the bound at `tests/character_fit.mjs:366`.

2. **`tests/character_fit.mjs`, the halo case and the fit loop:**
   - **The `skin halo` case's `on`** (`:339-340`, built for each skin in the `for` loop). For `skin === "halo"` only,
     append browser-side code after `applyLook(...)`:

     ```js
     const h=SKIN_PARTS.halo, set=h.setAttribute.bind(h); window.__haloPins=0;
     h.setAttribute=(k,v)=>{ if(k==='transform'){ window.__haloPins++; v='translate(0,'+(-HALO_FLOAT)+')'; } return set(k,v); };
     h.setAttribute('transform','');
     ```

     **Write it exactly like this, with string concatenation and no backticks and no `${…}`.** `on` is itself a Node
     template literal (`:340`): an inner backtick would end it, and a `${…}` would be evaluated by Node, where
     `HALO_FLOAT` doesn't exist.
   - **A `guard` field on the halo case only,** holding browser-side code (a plain string, with no backticks inside)
     that ends with an explicit `return [ok, detail]`. It starts with
     `const h=SKIN_PARTS.halo; if(!h) return [false,'no halo drawn'];`, so a missing halo fails the check instead of
     throwing:
     - `ok` holds when all of these are true:
       - `SKIN_PARTS.halo` is connected (`isConnected`)
       - `!SKIN_PARTS.halo.style.transform`
       - `SKIN_PARTS.halo.getAttribute('transform') === 'translate(0,'+(-HALO_FLOAT)+')'`
       - `window.__haloPins > 1`
     - `detail` holds the attribute, the style and the count.
   - **In the fit loop**, between the fit `check(...)` (`:367`) and `if (c.after)` (`:368`), add:
     `if (c.guard) { const [g, d] = await ev(c.guard); check(g, `${ID}: ${c.name} stays pinned at the float's top`, d); }`.
     `check` records a failure without throwing, so `c.after` always runs and removes the halo with the wrapper.

   → verify:
   - `nix develop .#ci -c python3 -B .github/ci/run_tests.py --deadline 1800 test_character_fit.py` is `ok`.
   - Every character with the halo shows both checks passing: "skin halo fits" and "stays pinned". Read them in the
     runner's output.

   Traps:
   - Never start Chromium yourself. Only the test may, headless with `--disable-gpu` (a GPU Chrome hung p620's AMD GPU
     twice).
   - Don't touch the bound at `:366`, the other cases, or the sampling code.
   - The test reads the halo as `SKIN_PARTS.halo`. That holds because `drawSkin` returns `parts` with `halo`
     (`:1294`) and `:1183` stores it in `SKIN_PARTS`.

3. **The regression proof** (lead, no commit):

   → verify: three red runs of "skin halo fits", one red "stays pinned", then `git diff` is clean against step 2.
