# Plan: WhatsApp in Nixi

This plan stands on its own: it carries every approved decision.

## Approved decisions

**Scope**
- **D1.** WhatsApp is built into Nixi, like the phone.
- **D2.** Each host pairs as its own linked device, using 2 of the 4
  slots. The owner accepted the ban risk.
- **D3.** Groups are read and download only. A group message raises a
  card only when it mentions the owner.
- **D4.** Voice notes show as "voice message" and can be downloaded, not
  played.
- **D5.** History: only the bridge store, removed by "Unlink and forget".

**Bridge**
- **D6. Code.** A fork of `lharries/whatsapp-mcp` at `7d6a06d`, the Go
  bridge only, MIT, with `LICENSE` and `NOTICE` kept.
  - Split into `main.go`, `api.go`, `store.go`, `send.go`, `read.go`,
    `pair.go` and `events.go`. Any file may be written fresh.
  - whatsmeow is pinned to `v0.0.0-20261125185702-10b99a98616e`.
  - A quiet logger: warn level and up, never debug, because the QR code
    is logged at debug.
- **D7. Startup.**
  - Flags `--state`, `--run` and `--max-file-mb 100`.
  - `umask(077)`.
  - SQLite in WAL mode with `busy_timeout=5000`. `messages.db` uses
    `SetMaxOpenConns(1)`, with indexes on `(chat_jid, timestamp)` and
    `rowid`.
  - Clear `RUN/stage` and `RUN/dl`.
  - Write the token atomically: 32 bytes to `token.tmp`, fsync, rename to
    `RUN/token` (0600). Generate a random `boot` id.
  - Unlink a stale socket, listen on `RUN/sock`, chmod it 0600.
  - Exit non-zero only if the store or socket fails. WhatsApp errors
    become states. No TCP.
- **D8. API.** Every request needs `Authorization: Bearer`, compared in
  constant time; otherwise 401.

  | Method and path | Does |
  |---|---|
  | `GET /status` | `{boot, state ∈ unpaired, pairing, connecting, ready, relink, outdated, error, me}` |
  | `POST /pair` | Starts or reads the **single** pairing session (`GetQRChannel` before `Connect`, empty store only). Returns the current QR as a PNG data URL with `expires_at`. Terminal events end it. |
  | `POST /pair/cancel` | Ends the session. |
  | `POST /forget` | Stops handling, tries `Logout` and ignores a failure, deletes both DBs with `-wal`/`-shm`, `stage` and `dl`. Replies 200, flushes, exits 0. |
  | `GET /chats`, `GET /contacts`, `GET /thread` | The fields in D9. |
  | `GET /new?after=<rowid>` | Live incoming messages only (never `history`): `{rowid, jid, id, at, is_group, mentions_me, sender_jid}`. No text. |
  | `POST /send` `{jid, text}`, `POST /send-file` `{jid, staged, caption?}` | `{result, id?}` |
  | `POST /download` `{jid, id}` | `{file, name}`. `file` is generated, in `RUN/dl`. |

- **D9. Read fields.**
  - Chats: `{jid, name, is_group, last_at, unread, last_preview}`.
  - Contacts: direct JIDs only.
  - Thread: `{id, from_me, sender_name, at, text, kind, caption,
    file_name, size, edited, deleted}`.
- **D10. Send rules (both endpoints).**
  - Only direct users (`s.whatsapp.net`, `lid`), normalised through the
    LID map. Groups, broadcast and newsletters get `not_sent`.
  - The client must be logged in (`IsLoggedIn()`) and connected,
    otherwise `not_sent`.
  - The result is `sent` only when `err == nil`. An error or timeout after
    the call is `unknown`. Before the call, it is `not_sent`.
  - No retries in the bridge.
  - `staged` must match `^[A-Za-z0-9_-]{16,64}$`. It is opened relative to
    an `O_DIRECTORY` handle with `O_NOFOLLOW`, must be a regular file
    (fstat), must be under the limit, and is read through the open handle.
  - It is deleted only once `SendMessage` was called. On `not_sent` it is
    kept.
- **D11. Downloads.**
  - Download with `DownloadMediaWithPath` from the stored `DirectPath` and
    keys. No URL rebuild (this fixes upstream #382).
  - The name is `<unix-ms>-<random>.<ext>`, with `ext` matching
    `^[a-z0-9]{1,8}$` or else `bin`.
  - Write with `O_EXCL`, under a byte limit; remove partial files.
- **D12. Events.**
  - `mentions_me`: any `ContextInfo.MentionedJID` that normalises to the
    owner's phone-number or LID JID.
  - Edit: whatsmeow sets `IsEdit` and unwraps it. Update the original
    key's text and set `edited`.
  - Revoke and `DeleteForMe`: a tombstone (text and keys cleared,
    `deleted` set). Inserts use `ON CONFLICT DO UPDATE … WHERE
    deleted = 0`, so content never comes back.
  - History sync: `history = 1`.
  - `LoggedOut`: state `relink`.
  - Logs carry no text, names, JIDs, QR codes or paths.

**Nix**
- **D13. Packaging.** `nix/whatsapp-bridge.nix` builds with
  `buildGoModule` (CGO on, `doCheck`). The flake exports
  `packages.nixi-whatsapp-bridge`, and the dev shell gets `go`.
- **D14. nixi-nixarchy `nix/hm-module.nix`.**
  - New options `services.nixi.companion.whatsapp.{enable, package}`.
  - It defines `systemd.user.services.nixi-whatsapp`:
    - `ExecStart` is the bridge with `--state $STATE_DIRECTORY --run
      $RUNTIME_DIRECTORY`;
    - `StateDirectory`/`RuntimeDirectory=nixi-whatsapp`, `Mode=0700`;
    - `UMask=0077`, `Restart=on-failure` and `NoNewPrivileges=yes`;
    - **no `WantedBy`**.
  - It writes a read-only `nixi-companion/whatsapp.json`:
    `{"bridge": true, "unit": "nixi-whatsapp.service"}`, like
    `peers.json` (`hm-module.nix:382`).

**Nixi**
- **D15. Client `app/whatsapp.py`.**
  - Before each connect: `RUN` is ours and 0700, and `sock` is a socket
    we own, as `phone.py:56–62` does.
  - The token is read with `O_NOFOLLOW`, and the peer uid is checked with
    `SO_PEERCRED` after connect.
  - Errors are `NotSent` and `Unknown`. Losing the reply after the request
    was written counts as `Unknown`.
  - `stage(stream, n)` streams into `RUN/stage/<token_urlsafe(24)>`
    through a directory handle, with `O_CREAT|O_EXCL|O_NOFOLLOW` 0600 and
    a byte counter. Partial files are removed.
  - `fetch(file)` checks the name pattern, then **copies** (never
    renames, since this may cross filesystems) to `~/Downloads/WhatsApp/`
    (0700). The destination is opened `O_EXCL` 0600, with `-1`, `-2` on a
    clash. Partial files are removed, and the source is unlinked in
    `finally`.
  - A poller thread runs only while `whatsapp_on` is set, independent of
    `Phone`.
- **D16. Server state.**
  - `WA_LOCK` guards `WA_GEN = (counter, boot)`, `WA_DRAFT` (one-use, 600
    s) and `WA_FILE` (a staged name bound to `jid`, file name, size and
    draft).
  - No I/O under the lock, and it is never held with `Call.lock` or
    `PHONE_LOCK`.
  - The generation is bumped **before** stopping, on: off, lock, unlink,
    or a `boot` change.
  - Each operation: (a) under the lock, check the generation and consume;
    (b) do the I/O outside; (c) under the lock, re-check the generation and
    card id before publishing.
  - The commit point is the request written to the socket. After that,
    the result is always shown, and `unknown` is never re-armed.
  - Staged files are deleted on cancel, on expiry (a sweep every 60 s), on
    replace, off, lock and start.
- **D17. Setting `whatsapp_on`.**
  - It shows only when `whatsapp.json` has `bridge: true`.
  - On: `systemctl --user start` the unit.
  - Off: bump the generation, `Store.forget_where` the `wa_*` cards
    (`stages.py:660`), delete staged files, then stop the unit.
  - At login, start the unit when the setting is on.
  - "Unlink and forget" is click-only: call `/forget`, then set
    `whatsapp_on=false`.
- **D18. Cards.** Seven kinds: `wa_pair`, `wa_chats`, `wa_thread`,
  `wa_draft`, `wa_file`, `wa_summary` and `wa_new`.
  - All are added to `phone_on_screen` (`server.py:7814`), the private
    list (`stages.py:430`), and the `drafting` guard in **both**
    `phone_tick` (`server.py:8083`) and the WhatsApp poller.
  - `wa_thread`: direct chats get Reply, Send a file, Summarise and
    Suggest a reply. Groups get Download only.
  - `wa_pair` closes on lock, on cancel or after 3 minutes, and calls
    `/pair/cancel`.
  - `wa_new` names the sender only when `notify_details` is on.
- **D19. Endpoints.**
  - `send`, `send-file`, `download` and `forget` need `CLICK_KEY` and a
    trusted pointer `isTrusted` event, as in the #121 call cards.
  - `stage` needs `CLICK_KEY` and an open `wa_file` draft. It is uploaded
    on `change` or `drop`.
  - `pair`, `thread` and `summary` are show-only.
  - On `unknown`: "May have been sent: check your phone."
- **D20. Poller.**
  - It polls `/new` every 10 s while `ready`, with a local `rowid` cursor.
  - Direct messages, or group messages that mention the owner, queue a
    `wa_new` card. The quiet rules are re-checked when it shows.
  - WhatsApp Web rows (`server.py:3523`) do not become cards while the
    bridge is `ready`.
- **D21. Phrases** `wa_read`, `wa_open`, `wa_reply`, `wa_file` and
  `wa_summary`, in en, nb and pl.
  - `wa_summary` only opens the chat.
  - `/api/ask` (`server.py:11026`) checks the WhatsApp word list **before**
    the prompt, plugin or history, and answers with a local card. That
    covers attachments, `opts.claude` and a failed quick call.
  - The page's stage-to-speech fallback (`index.html:3975`) skips `wa_*`.
- **D22. Summary.**
  - It runs from a click on an open **direct** `wa_thread`, bound to its
    `jid` and generation.
  - At most 50 messages or 8,000 characters, sent as a JSON array of
    `{from: me|them, text}` on stdin, with sender names dropped.
  - The fixed instruction goes in `--system-prompt`.
  - The command: `claude -p --safe-mode --model haiku --tools ""
    --no-session-persistence --strict-mcp-config --disable-slash-commands
    --exclude-dynamic-system-prompt-sections`, with a 30 s timeout and an
    empty temporary `cwd`.
  - The binary comes from `oneshot_bin()`: `NIXI_CLAUDE`, else
    `shutil.which`.
  - It runs in Nixi mode too. `docs/GUIDE.md:10` gets a note saying so.
  - The output is plain text, at most 1,500 characters, re-checked
    against the card and generation. "Suggest" fills a new `wa_draft`.
- **D23. Agent guards.**
  - `_WA_RE = /whatsapp|messages\.db/i` runs on `_is_flux`'s three cleaned
    variants (`server.py:988–1005`). It is ORed into `click_only`
    (`:1008–1012`), and `send_detail` gets `kind: "whatsapp"`.
  - Every Claude settings file Nixi writes gets `permissions.deny` for
    `Read`/`Edit`/`Write` on the WhatsApp state, run and download folders,
    and `Read` on `runtime.json`. That covers `hooks_file()`,
    `send_hooks_file()` and a new deny-only settings file for `readonly`.
  - nixi-nixarchy adds the same rules for its Claude ACP adapter, a path
    check on `Read`/`Grep`/`Glob` in its permission handler, and
    `isWhatsapp` ORed into `isClickOnly`.
  - `/api/capture` (`server.py:10825`) refuses while a `wa_*` card is
    current, through `phone_on_screen`. `capture()` re-checks after the
    image is taken and discards it if a card appeared.
- **D24. Rollout.** p620 first. razer only after the live gate (step 11).
  p510 is never touched.

## Steps

All steps in this repo use the worktree `../nixoarchy-126-whatsapp`,
branch `feat/126-whatsapp`. Step 10 uses a new nixi-nixarchy worktree,
branch `feat/126-whatsapp`.

1. **Lead: prove the CLI assumptions.** No edits.
   - With the installed `claude`, show that a `permissions.deny`
     `Read(<tmpdir>/**)` rule blocks a read under `--permission-mode
     bypassPermissions` and under `plan`, using a throwaway file.
   - Show that `--safe-mode` and `--system-prompt` work with `-p`.
   - Record the results under Deviations.
   - If deny does **not** hold under bypass: D23 adds a
     `Read|Grep|Glob` matcher to `send_hooks_file()` that denies those
     paths in `approve.py`.
   - If `--safe-mode` is missing, summaries are off: fail closed.
2. **`whatsapp-bridge/` core: vendor, split, whatsmeow bump, store,
   events.** Codex.
   - Covers D6, D7 (stores only) and D12.
   - Fetch upstream at `7d6a06d` into a scratch directory. Copy
     `whatsapp-bridge/` with `LICENSE`, and add `NOTICE`.
   - Check: `cd whatsapp-bridge && nix develop .. -c go build ./... && go
     test ./...` (store and event tests).
   - Traps:
     - no network in tests;
     - never pair or connect to a real account;
     - logs carry no text, names, JIDs or QR codes.
3. **`whatsapp-bridge/` API: socket and token, send, staging, downloads,

   - Covers D7 (socket and token), D8, D10 and D11.
   - Go tests for every case in the spec's Go list: token, 401, atomic

## Rollback

- Turn WhatsApp off in Settings: the unit stops and the cards go.
- To remove it, revert the nixos_config enable, which drops the unit, and
  redeploy.
- Revert the PRs if needed.
- "Unlink and forget" first if the linked device should go too. Otherwise
  remove it from the phone's Linked devices.
