# Plan: accept an ElevenLabs key from sops-nix

## Summary of the approved spec

- `app/eleven.py` accepts a key file whose resolved path is under `/run/secrets.d`, as the sops-nix NixOS module lays
  it out: `/run/secrets` is a link to `/run/secrets.d/<gen>`.
- The four allowed roots become a module constant `KEY_ROOTS`, so a test can point them at a temporary layout. Its
  entries are **not** resolved with `realpath`.
- Every other check stays as it is:
  - `realpath` of the configured file, then the root check
  - the `O_NOFOLLOW` open
  - the `fstat` checks: regular file, 1–256 bytes, owner root or the user
  - the key regex
  - no key text in errors
- **Trust assumption:** `O_NOFOLLOW` guards only the last path component. Containment also relies on every directory
  from `/run` down to the secret being owned by root and **not writable by Nixi's user**, which holds for agenix and the
  sops-nix NixOS module. A read during a sops-nix generation switch may fail once.
- **Out of scope:** Home Manager sops-nix, `neededForUsers` secrets and a custom mount point. Group-shared secrets
  are still refused.
