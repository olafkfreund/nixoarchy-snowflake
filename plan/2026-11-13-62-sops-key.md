# Plan: accept an ElevenLabs key from sops-nix

## Summary of the approved spec

- `app/eleven.py` accepts a key file whose resolved path is under `/run/secrets.d`, as the sops-nix NixOS module lays
  it out: `/run/secrets` is a link to `/run/secrets.d/<gen>`.
- The four allowed roots become a module constant `KEY_ROOTS`, so a test can point them at a temporary layout. Its
  entries are **not** resolved with `realpath`.
- Every other check stays as it is:
  - `realpath` of the configured file, then the root check
  - the `O_NOFOLLOW` open
  - the `fstat` checks: regular file, 1–256 bytes, owner root or the user
  - the key regex
  - no key text in errors
- **Trust assumption:** the directories from `/run` down are root-owned. A read during a sops-nix generation switch
  may fail once.
- **Out of scope:** Home Manager sops-nix, `neededForUsers` secrets and a custom mount point. Group-shared secrets
  are still refused.

     ```nix
     {
       # sops-nix (NixOS module) -> /run/secrets/api-elevenlabs, a file in /run/secrets.d/<generation>/
       sops.secrets.api-elevenlabs = {
         owner = "<your-user>";        # sops-nix defaults to root:root 0400, which he can't read
       };
     }
     ```

     Then one line saying to set `"eleven_key_file": "/run/secrets/api-elevenlabs"` in

3. **`tests/test_eleven.py`, after `test_key_symlink_and_rejections` (`:61-81`):** add `test_key_from_sops_layout`:
   - **The real roots**, before any patch: `self.assertEqual(eleven.KEY_ROOTS, ("/run/agenix", "/run/agenix.d",
     "/run/secrets", "/run/secrets.d"))`.
   - **Setup:** `base = Path(os.path.realpath(self.tmp.name))`, because the roots aren't resolved and `$TMPDIR` may be

   - **Read:** `self.assertEqual(eleven._key(), KEY)`.
   - **Generation switch:** write a second valid key (e.g. `"new-fake-key-5678abcd"`) to `secrets.d/2/api-elevenlabs`.
     `unlink` `secrets`, re-link it to `secrets.d/2`, and assert `_key()` returns the new key.
   - **Escapes:** replace `secrets.d/2/api-elevenlabs` with a link to a file outside both roots (`base / "outside"`,
     holding `KEY`). Assert `has_key()` is False. Then point it at `base / "secrets.d-evil/key"`, also holding `KEY`,

   → verify: `python3 -B tests/test_eleven.py` passes. Also check that the new test fails with step 1 reverted

   - Never import `server`, and never touch the real HOME or `/run` (memory: tests under `nixi_env`).
