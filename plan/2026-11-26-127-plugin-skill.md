# Plan: a skill for making and sharing Nixi plugins

This plan stands on its own: it carries every approved decision.

## Approved decisions

- **D1. Where it lives.** The skill is in this repo, at
  `skills/nixi-plugin/`. The template is at `skills/nixi-plugin/template/`.
  It is never under `plugins/`, because `app/plugins.py:63–65` and
  `:320–321` would load it as a plugin from a checkout.
- **D2. No runtime change.** Nothing under `app/` changes, and neither do
  the sandbox tests.
- **D3. The walkthrough in SKILL.md.**
  1. **Choose the kind.** A table of quips, prop, character,
     notifications, reactions and stage, each with the example to copy.
     None of the examples shows a character or reactions.
  2. **Copy the template.** Use `cp -rL --no-preserve=mode` from the
     `template/` next to `SKILL.md`, then `chmod +x run`. Rename the `id`
     and the phrase.
  3. **Check.**
     - Run `nix build --no-link` in the plugin folder. Its flake calls
       `mkCompanionPlugin`, which runs `--check` (`nix/plugin.nix:19`).
       Always use `--no-link`: a `result` symlink is refused
       (`app/plugins.py:327`, `:1039`).
     - Then install it into `$XDG_DATA_HOME/nixi-companion/plugins/`
       (default `~/.local/share/...`) and turn it on in Settings → Plugins.
       Only stage plugins show the consent prompt (`docs/GUIDE.md:490–491`,
       `:504–505`).
     - Stage plugins: say the phrase and see the card. Props and
       characters: choose them in Settings → Look as `plug:<id>`. Check
       that quips, the notification category or the reaction appears.
     - The sandbox needs `bwrap`, plus `pasta` and `ip` when `network` is
       true. Give the error lines to expect.
     - **Private characters branch off here.** They stay a local folder
       (`chmod -R go=`), with no `--check`, Nix or publishing
       (`plugins.py:1036`, `GUIDE.md:492–495`).
  4. **Install.** Use `services.nixi.companion.plugins` (from nixi's Home
     Manager module), or keep it as a folder plugin.
  5. **Share.** Put it in its own repo with the template's flake. Add the
     GitHub topic `nixi-plugin`. Users add it as a flake input and list
     `inputs.<name>.packages.<system>.default` in
     `services.nixi.companion.plugins`.
- **D4. The "never" list.** Each rule cites where it is enforced:
  - `network` together with `reads` (`plugins.py:219–224`);
  - `argv[0]` outside the folder (`:225–226`);
  - absolute or `..` arguments (`:227–228`);
  - symlinks and hard links;
  - `videos`, which is for `news` only (`:203–204`);
  - skipping the SVG limits (`:462–578`);
  - committing a private character (`GUIDE.md:492–495`).
- **D5. The template.**
  - `plugin.json`: `api: 1`, `id: "my-plugin"`, a stage with one unique
    phrase, `argv: ["run"]`, `network: false`, and no `reads`.
  - `run`: `#!/usr/bin/env python3`, mode 0755. It prints one static
    object: `{"v": 1, "kind": "facts", "title": …, "points": [two
    strings]}`. That is the schema at `app/stages.py:138–150`. The sandbox
    has `/usr/bin/env` but no `/bin/sh` (`plugins.py:664`).
  - `README.md` and an MIT `LICENSE`, with the notice copied from
    `plugins/examples/*/LICENSE`.
  - `flake.nix`: the only input is
    `nixi.url = "github:olafkfreund/nixoarchy-snowflake"`, and
    `packages = builtins.mapAttrs (_: l: { default = l.mkCompanionPlugin
    { pname = "my-plugin"; src = self; }; }) nixi.lib;`.
- **D6. The reference pages hold labelled tables, one per field:**
  - manifest keys, prop keys, character keys and stage keys;
  - categories, reactions and round fits;
  - `reads`, with each feed's stdin fields. `phone-status` is only name,
    online, battery and charging, while Phone is on. `phone` and `peers`
    may be absent.
- **D7. The drift test.** `tests/test_plugin_skill.py`:
  1. `plugins.check_dir(template)` returns no error.
  2. The template runs in the real sandbox and returns the expected
     `points`:
     - `run_stage(p, …, fresh=True)`;
     - an isolated `plugins.State` with the template enabled at its hash;
     - `plugins.State` patched to return it, as in
       `tests/test_plugin_sandbox.py:25` and `:47`.

     It is skipped when `plugins.bwrap_ok()` is false, and fails instead
     under `NIXI_SANDBOX_TESTS=require`, which the dev shell sets.
  3. Each labelled table matches its own set: `REQUIRED|OPTIONAL`,
     `PROP_KEYS`, `CHARACTER_KEYS`, `STAGE_KEYS`, `CATEGORIES`,
     `REACTIONS` and `ROUND_FITS`. `reads` is checked against the values
     at `plugins.py:217`, through `_check` on a sample manifest.
  4. There are no symlinks under `skills/nixi-plugin/`, and the template
     has no `private` key.

  The docstring says: "update skills/nixi-plugin/reference when the plugin
  API changes". The same reminder ends `SKILL.md`.
- **D8. The flake check.** `nixi-plugin-template` builds
  `mk { pname = "nixi-plugin-template"; src = ./skills/nixi-plugin/template; }`.
  It sits next to `broken-manifest-fails` (`flake.nix:137`, using `mk` at
  `:82`).
- **D9. Docs.**
  - `docs/GUIDE.md` Plugins section (`:460`): one line linking to
    `../skills/nixi-plugin/SKILL.md`.
  - "any of five parts" (`:477–478`) becomes six, with a `- **reactions:**`
    bullet in the list at `:480–502`.
  - `README.md`: one line in the plugins paragraph.
- **D10. Rollout.**
  - nixos_config: `Users/olafkfreund/p620_home.nix` (add `inputs` to its
    arguments) and `razer_home.nix` each get
    `home.file.".claude/skills/nixi-plugin".source = "${inputs.nixi-companion}/skills/nixi-plugin";`.
    That is one directory link.
  - **Not** `localSkills` or `profile.nix`: p510 imports both.
  - It goes in the same PR as the `nixi-companion` bump, after this repo
    merges.

## Steps

1. **`skills/nixi-plugin/` (new): SKILL.md, reference pages and
   template.** agy.
   - Files:
     - `SKILL.md`, with frontmatter `name: nixi-plugin` and a
       `description` of trigger words: "make a Nixi plugin", "Nixi
       companion plugin", "share a plugin";
     - `reference/manifest.md`, `reference/stage.md`,
       `reference/sharing.md` and `reference/private.md`;
     - `template/{plugin.json, run, README.md, LICENSE, flake.nix}`.
   - Follow D3–D6. Read the facts from `app/plugins.py`, `app/stages.py`,
     `docs/GUIDE.md:460–525` and `plugins/examples/`. Never invent a key.
   - Also make the docs edits in D9.
   - Check:
     - `nix develop -c python3 app/plugins.py --check skills/nixi-plugin/template`
       prints `ok`;
     - `test -x skills/nixi-plugin/template/run`.
   - Traps:
     - keep `run`'s executable bit;
     - no symlinks;
     - the template's phrase must not clash with Nixi's reserved phrases
       (`plugins.py:229–231`).
2. **`tests/test_plugin_skill.py` (new) and the flake check.** Codex.
   - Write the test per D7 and the check per D8.
   - Check:
     - `nix develop -c python3 -B -m unittest tests/test_plugin_skill.py`;
     - `nix build .#checks.x86_64-linux.nixi-plugin-template`.
   - Traps:
     - never touch the real `~/.local/share/nixi-companion`;
     - patch `plugins.State`, as `test_plugin_sandbox.py:47` does.
3. **Lead: integrate, verify, review, PR.**
   - Rerun the step 1–2 checks.
   - Build a copy of the template:
     `cp -rL --no-preserve=mode skills/nixi-plugin/template /tmp/x && chmod +x /tmp/x/run && cd /tmp/x && nix build --no-link --override-input nixi path:<worktree>`.
   - Run `test_plugins.py`, `test_plugin_sandbox.py` and the full suite.
   - Run `nix flake check`.
   - Reviews: a fresh Opus review against this plan, plus the
     cross-reviews.
   - Open a PR that links all three artifacts, with "@codex review". This
     PR touches no `app/plugins.py`, so no sandbox-test PR note is needed
     beyond the test run.
4. **Lead: rollout.**
   - After merging, one nixos_config PR bumps `nixi-companion` and adds D10.
   - Build p620 and razer. Only **evaluate** p510's toplevel; do not build
     it.
   - `nh os switch` on p620, then `just deploy-via-p620 razer`.
   - Check on both: `~/.claude/skills/nixi-plugin/SKILL.md` exists, and a
     copy made by the skill's own recipe passes `nix build --no-link`.
   - Once the merged URL exists, check it once with a plain `nix build`.
   - Manual check: a copy with a new `id` installs as a folder plugin on
     p620 and shows its card after consent. Record it in the PR.
