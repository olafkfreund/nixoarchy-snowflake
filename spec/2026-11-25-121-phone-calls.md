# Spec: place phone calls from Nixi, with contact names on the handset

Everything here runs over Bluetooth on the host. Calling and name lookup
must work with Flux offline. Flux and the Android app are not changed.

## Design

### 1. Phonebook: `app/pbap.py` (new)

A small client of BlueZ's `obexd` on the session bus
(`org.bluez.obex`), using Gio like `app/hfp.py`.

- `Pbap.load(address)`:
  1. `Client1.CreateSession(address, {"Target": "pbap"})`.
  2. `PhonebookAccess1.Select("int", "pb")`.
  3. `PullAll(path, {"Format": "vcard30", "Fields": ["FN", "N", "TEL"]})`,
     into a file in a new `0700` directory under `$XDG_RUNTIME_DIR`.
  4. Wait for the `Transfer1` to finish, with a 20 s limit.
  5. Parse the file, then delete the file and directory and call
     `RemoveSession`, in a `finally`, so a failure, timeout or crash
     path leaves nothing behind. On startup, stale `nixi-pbap-*`
     directories are removed too.
- **Parsing:** for each contact, the display name (`FN`, falling back to
  `N`) and every `TEL` with its type mapped to a label: mobile, home,
  work, or other. Numbers are kept as written, and are also normalised to
  a digits-only key (the last 8 digits, as `Call._number` already
  matches).
- **The cache** is held per Bluetooth address, in memory only:
  - `{"at": monotonic, "contacts": [...], "by_number": {key: (name, label)}}`;
  - it lasts 10 minutes (intent decision 2);
  - it is dropped when that phone's gateway disappears from `Hfp`, when
    Phone is turned off (`phone_on`), and when the desktop locks.
  - A load runs on a worker thread. Only one load runs per address at a
    time, and callers get "loading" rather than waiting.
- `Pbap.name_for(address, number)` returns `(name, label)` or `None`,
  from the cache only, without blocking.
- `Pbap.search(address, query)` matches names case- and accent-insensitively:
  exact match, then word-prefix match, then substring match. It returns
  at most 8 people, each with all their numbers.
- **Errors map to three states:** "no phone" (no session),
  "contact sharing is off" (`CreateSession` or `Select` refused, which is
  how Android reports PBAP not authorised), and "failed".
- Nothing here logs names or numbers. Errors are logged by type only, as
  `phone.py` does.

### 2. Dialing: `Hfp.dial()` in `app/hfp.py`

- `Hfp.dial(ag_path, number)` calls `AudioGateway1.Dial(s)` on that
  gateway through the existing `_action`/`_call` pattern. It returns
  `{"ok": True}`, or `{"ok": False, "error": "busy" | "gone" | "failed"}`.
- It refuses when `any_call()` is true, because dialing during a call can
  put that call on hold, or when the gateway path is not in
  `self.gateways`.
- `Hfp.gateways` already maps each gateway path to its `Address`.
  `Hfp.gateway_list()` returns `[(path, address, alias)]`, with the alias
  read from BlueZ (`org.bluez.Device1.Alias`), for the picker and for
  PBAP.

### 3. Which phone (`app/server.py`)

Flux device rows carry no Bluetooth address (`app/phone.py:121-138`), so
a Flux device cannot be matched to a Bluetooth gateway. Intent decision 3
("the Flux-paired device dials") cannot be done reliably. This spec
replaces it, and needs the owner's OK:

- one HFP gateway connected: it is used;
- several: the pick card lists the Bluetooth phones by their alias, and
  the chosen gateway is carried into the confirmation;
- none: "Your phone isn't connected over Bluetooth."

**Caller names** always come from the phonebook of the phone carrying
that call: the address of the call's gateway (`h["ag"]`). A Flux-only
call, with no HFP leg, keeps Flux's own caller name and does no phonebook
lookup.

### 4. The handset name (`Call.sync`, `app/server.py:8085-8196`)

- After `who` and `number` are worked out (`:8161-8162`):
  - if `who` is empty, or is just digits (the phone sent the number as
    its name), and the call has an HFP leg with a number, it looks up
    `Pbap.name_for(address, number)`;
  - on a hit, `who` becomes the contact name and a new field `label`
    holds the number's label;
  - if `who` came from the phone and is a real name, it is kept, and
    `label` is added only when the phonebook has that exact number;
  - with no number (withheld) or no hit, the display is as today: the
    number, or the localized "Unknown caller".
- **The cache is never waited on.** On a miss while it is cold, `sync`
  starts a background load. When the load finishes, `Call.sync()` runs
  again, so the name appears a moment later.
- The handset (`HS.text`, `index.html:3708`) shows `who`, plus `· label`
  when present, on the big display and in the compact bar pill.
- **Privacy:**
  - phonebook names are display-only. They are not passed to the spoken
    ring announcement (`phone_on_call`, `:8344`), which keeps using only
    the phone-sent name, because Nixi's voice is ElevenLabs (cloud);
  - the missed-call card (`call_missed`, `:7997`) gets the phone-sent
    name only, not the phonebook one. Missed cards persist in
    `PHONE_MISSED` and can be read aloud.

### 5. Outgoing call states (`Call.sync`)

- HFP `dialing` and `alerting` become a new `phase` `"dialing"`, with:
  - `path` `"host"`;
  - `keys` `["hangup"]`, whatever `audio_here` says;
  - `answered_at` `None`.
- `phase` `"active"` (and `answered_at`) starts only when HFP reports
  `active`. Today's code maps every non-ringing state to active
  (`:8159`).
- Ending:
  - `dialing` → `disconnected` shows "Call ended" for 2 seconds through
    the existing ended path (`end_timer`), not as a missed call;
  - `hfp_incoming` stays false for an outgoing call, so `call_missed`
    never fires for it.
- `Ambient.phone_call` follows HFP's `any_call()` as today, so Nixi goes
  quiet and frees the mic as soon as dialing starts.
- The handset shows "Calling…" (`call.dialing`) with the hang-up key,
  and the phone icon (not the bell).

### 6. "Call …": voice and typed (`app/quick.py`, `app/server.py`)

- **Phrases**, per language in the locale `phrases` lists, the way the
  existing phone phrases work (`quick.py:335-356`):
  - English: `call <x>`, `phone <x>`, `ring up <x>`, `dial <x>`;
  - Norwegian (`nb`) and Polish (`pl`) equivalents.
  - `<x>` is one to four words, or a number.
- **Boundary, so "call that function" still reaches the agent:** the
  phrase is taken locally only when the phone feature is on, and `<x>`:
  - is a valid number (as defined below), or
  - is one to four words with no article or code word (`the`, `that`,
    `this`, `a`, `an`, `function`, `method`, `api`, `it`, and their `nb`
    and `pl` equivalents).
  When taken locally, it never falls through to the agent, even if
  nothing matches, Bluetooth is down, or the phonebook is off. The reply
  is a local message. So a contact name never reaches the model.
- `phone_quick` gains `do == "call"`. It is checked before the
  `Phone.connected` gate, because calling needs only Bluetooth:
  - `phone_on` off: "Phone is turned off in Settings."
  - locked desktop: nothing is shown, as for other phone cards;
  - no gateway: "Your phone isn't connected over Bluetooth.";
  - a valid number: straight to the confirm card, after the gateway pick
    if there are several;
  - a name with the cache cold: "Looking up your contacts…", then the
    load, then the cards once it finishes. If sharing is off: "Turn on
    Contact sharing for this computer in your phone's Bluetooth
    settings.";
  - 0 matches: "I couldn't find <x> in your contacts.";
  - one person with one number: the confirm card;
  - otherwise: the pick card with one row per person and number. Each
    row shows the name, label and a masked number (`…1234`).
- **Typed requests** go through the same `quick.handle` path as voice.
- **What is kept:** the utterance is handled like other local quick
  phrases. The reply text is the only thing that enters history, and
  replies never include a full number.

### 7. Cards and confirmation (`app/server.py`, `app/static/index.html`)

- **The cards:**
  - the pick card is stage kind `phone_call_pick`;
  - the confirm card is stage kind `phone_call_confirm`, showing name,
    label and the full number, with one **Call** button;
  - both follow `stagePhoneDraft` (`index.html:3419`). A button acts
    only for a trusted pointer click
    (`e.isTrusted && ['mouse','pen','touch'].includes(e.pointerType)`)
    and sends `CLICKKEY.hdr()`. Enter or Space does not dial.
- **The confirmation is held server-side,** like `PHONE_DRAFT`
  (`:7807-7860`), as `PHONE_DIAL`:
  `{id, gateway_path, address, number, name, label, created, gen}`. Only
  the id goes to the page. A new pick or confirm replaces any older one,
  so two cards can never both dial.
- **`POST /api/phone/dial {dial: id}`** requires `click_ok(X-Nixi-Click)`.
  Under `PHONE_LOCK`, it consumes `PHONE_DIAL` only if all of these hold:
  - the id matches, it is younger than 60 s, and `gen == PHONE_GEN`;
  - `phone_on` is on and the desktop is unlocked;
  - the gateway path is still connected with the same address;
  - `Hfp.any_call()` is false and `Call.visible()` is false.
  Otherwise it returns 403 and `{"ok": False, "say": …}` with the reason.
- After it is consumed, `Hfp.dial` runs once. A failure does not put the
  confirmation back. The owner asks again, because a lost reply may mean
  the call went through. The handset then appears from HFP's
  `InterfacesAdded` through `Call.sync`.
- A pick-card row calls `POST /api/phone/dial-pick {row: token}`, also
  click-gated. It turns that row into a fresh `PHONE_DIAL` and shows the
  confirm card. The pick never dials directly.

### 8. Allowed numbers

After removing spaces, dashes, dots and brackets:

- the number is `+?[0-9]{6,15}`;
- that excludes MMI and USSD (`*`, `#`), pauses and post-dial strings
  (`,`, `;`, `p`, `w`), and service codes;
- emergency and short numbers (3-5 digits: `112`, `911`, `999`, `110`,
  `113`, short codes) are refused, with "For emergency or short numbers,
  use your phone." Dialing them from a desktop by voice is not worth the
  risk of a mistake.

### 9. Locale

New keys in `app/lang/en.json`, `nb.json` and `pl.json`, with English
fallback as today:

- `call.dialing`;
- `phone.call_off`, `phone.call_no_bt`, `phone.call_sharing_off`;
- `phone.call_loading`, `phone.call_not_found`, `phone.call_busy`;
- `phone.call_short`, `phone.call_failed`;
- `phone.call_pick_title`, `phone.call_confirm_title`,
  `phone.call_button`;
- the `phone_call` phrase lists.

## Alternatives rejected

- **Flux `call.dial` with `CALL_PHONE`.** It needs Android and daemon
  changes, a runtime grant, and works around Android's limits on
  starting activities in the background. The audio would also stay on
  the phone unless Bluetooth is up anyway.
- **adb `am start -a android.intent.action.CALL`.** Wireless debugging
  went offline during the check, and it hands Nixi a full device shell.
- **Flux `contacts.search`.** Works without Bluetooth, but needs Flux,
  APK and IPC changes. It stays as the fallback (intent decision 1).
- **PBAP `Search` per lookup instead of `PullAll` plus a cache.** Each
  incoming call would open a new OBEX session, which may prompt on the
  phone. The 10-minute cache was approved.
- **Speaking phonebook names in the ring announcement.** It would send
  contact names to a cloud voice.
- **Dialing directly from voice when there is one match.** Rejected by
  the intent: a click is always needed.

## Risks

- **PBAP authorisation:** the Pixel must allow contact sharing for each
  host. Until it does, names do not appear and "call <name>" says so.
  Number display and dialing typed numbers still work.
- **The `Dial` return shape and SCO timing are unverified on the live
  bus.** Whether the host hears the ringback while it is dialing is a
  hardware check.
- **Large address books:** the first `PullAll` can take a few seconds.
  It runs off the request thread, and the handset fills the name in when
  it is ready.
- **A vCard transfer file exists briefly on disk** in a private runtime
  directory. It is deleted in `finally`, and stale ones are deleted at
  startup.
- **Intent decision 3 is replaced** by the gateway picker (Design 3).
  This needs the owner's OK at spec approval.
- **The voice boundary** may take a phrase the owner meant for the agent,
  such as "call Bob's script". The stop-word list keeps the common cases
  out, and the reply says what it did.

## Verification

**Unit (all with fakes; no real phone, Bluetooth, adb or contacts):**

- `tests/test_pbap.py`, with synthetic vCards:
  - `FN`/`N` fallback, several `TEL`s with labels, odd and empty fields;
  - name search order and accents, and number lookup by the last 8
    digits;
  - the transfer file and directory are gone after success, error and
    timeout;
  - the cache expires after 10 minutes and is dropped on gateway loss,
    Phone off and lock;
  - only one load runs per address.
- `tests/test_hfp*.py`:
  - `dial()` with a fake connection: success, busy, gone, and a D-Bus
    error;
  - `gateway_list()`.
- `Call.sync`:
  - `dialing` → `alerting` → `active` → `disconnected`, asserting the
    phase, the keys, `answered_at` staying `None` until active, "Call
    ended", and no missed call;
  - incoming with a number only: the name and label from a warm cache;
    on a cold cache, the number first and the name after the load;
  - a real phone-sent name is kept;
  - a withheld number shows "Unknown caller";
  - the ring announcement and missed card never carry a phonebook name.
- `phone_quick` call:
  - Phone off, locked, no gateway, sharing off;
  - zero, one and several matches, and one person with two numbers;
  - a typed number, a short or emergency number, and a USSD code;
  - several gateways show the gateway pick;
  - "call that function" falls through, and "call Anna" never does.
- `/api/phone/dial`:
  - 403 without the click key;
  - a replay, an expired id, and two cards where only the newest dials;
  - a call that started after the card, and a gateway that disconnected;
  - `Hfp.dial` is called once.
- **Page:** the pick and confirm cards fit (`stages_fit.mjs` fixtures),
  the buttons ignore Enter/Space and untrusted clicks, and the handset
  shows "Calling…" with hang-up and `who · label` in both the display
  and the pill.
- **Regression:** the full suite.

**On hardware (p620, owner present):**

1. Turn on Contact sharing for p620 on the Pixel.
2. An incoming call from a saved contact shows its name and label on the
   handset.
3. "Call voicemail" (or the owner's chosen harmless contact): pick,
   confirm, click, "Calling…", host mic and speaker work, then hang up.
4. A typed number works the same way.
5. With Bluetooth off, the right message appears.

razer is checked the same way once the Pixel is paired with it.
