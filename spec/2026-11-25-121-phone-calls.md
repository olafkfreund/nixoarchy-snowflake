# Spec: place phone calls from Nixi, with contact names on the handset

Everything here runs over Bluetooth on the host. Calling and name lookup
work with Flux offline. Flux and the Android app are not changed.

## Design

### 1. Phonebook: `app/pbap.py` (new)

A small client of BlueZ's `obexd` on the session bus (`org.bluez.obex`),
using Gio like `app/hfp.py`.

**Loading** (`Pbap._load(address, gen)`, on a worker thread):

1. `Client1.CreateSession(address, {"Target": "pbap"})`.
2. `PhonebookAccess1.Select("int", "pb")`.
3. **Subscribe to the transfer's `PropertiesChanged` before
   `PullAll`.** Then call
   `PullAll(<absolute path>, {"Format": "vcard30", "Fields": ["FN", "N", "TEL"]})`,
   which returns `(transfer_path, props)`.
   - If `props["Status"]` is already `complete` or `error`, use that.
     Otherwise wait for a terminal `Status`, for up to 20 s.
   - On timeout, call `Transfer1.Cancel()` first.
   - The target file is in a new `0700` directory
     `$XDG_RUNTIME_DIR/nixi-pbap-<random>`.
4. Read the file only after `Status == "complete"`.
5. In a `finally`, delete the file and directory and call
   `RemoveSession`. On startup, any stale `nixi-pbap-*` directories are
   removed.

**Errors:**
- `CreateSession` failing with a not-authorised or forbidden error, or
  `Select`/`PullAll` refusing, means "contact sharing is off" (`sharing`).
- Any other `CreateSession` failure, such as unreachable or obexd
  missing, means "couldn't reach the phone's contacts" (`unreachable`).
- A failed or timed-out transfer means `failed`.

**Parsing:**
- The name is `FN`, falling back to `N`.
- Each `TEL` becomes `(label, number)`, with the type mapped to `mobile`,
  `home`, `work` or `other`. A `tel:` prefix, Unicode spaces and dashes
  are stripped.
- Each number gets a normalised key: digits only, with a leading `+`
  kept as a marker.
- Numbers that fail the number rule (Design 8) are kept for display,
  but marked as not dialable.

**The cache** is held per Bluetooth address, in memory only:

- `{"gen", "at", "state", "contacts", "by_key": {full_key: [(name, label)]}}`;
- it lasts 10 minutes (intent decision 2);
- **failure states are cached as well**, with a 5-minute backoff, so a
  phone with sharing off is not asked again on every call event;
- it is dropped, and the generation bumped, when that phone's gateway
  disappears, when Phone is turned off, and when the desktop locks;
- a worker started under an older generation discards its result. It
  can never fill the cache or publish cards after a lock, a disconnect or
  Phone being turned off;
- only one load runs per address at a time.

**Calls:**
- `Pbap.name_for(address, number)` reads the cache only and never
  blocks. It returns `(name, label)` when:
  - exactly one contact entry has the same full key, or
  - none does, and exactly one contact number shares the call number's
    last 8 digits.
  Two or more candidates means `None`. A suffix collision never shows a
  name.
- `Pbap.search(address, query)` matches names case- and
  accent-insensitively: exact, then word-prefix, then substring. It
  returns at most 8 people, with their dialable numbers only.
- `Pbap.state(address)` returns `ready`, `loading`, `sharing`,
  `unreachable`, `failed` or `cold`.
- Nothing here logs names or numbers. Errors are logged by type only.

### 2. Dialing: `Hfp.dial()` (`app/hfp.py`)

- `Hfp.dial(ag_path, number)` calls `AudioGateway1.Dial` with one string
  argument on that gateway path. It is its own call, not the `Call1`
  `_action` helper.
  - It refuses when `any_call()` is true, or when `ag_path` is not in
    `self.gateways`.
  - It returns `{"ok": True}`, `{"ok": False, "error": "busy"|"gone"}`
    for those refusals, or `{"ok": False, "error": "unknown"}` when the
    D-Bus reply is lost or times out.
  - `unknown` is ambiguous: the call may have been placed.
- `Hfp.gateway_list()` returns `[(path, address, alias)]`.
  - The alias comes from BlueZ on the **system** bus: the managed
    `org.bluez.Device1` whose `Address` matches. If BlueZ is unreachable,
    the address is used instead.
  - Two phones with the same alias are shown with the last 4 characters
    of their address added.

### 3. Which phone (`app/server.py`)

Flux device rows carry no Bluetooth address (`app/phone.py:121-138`), so
a Flux device cannot be matched to a Bluetooth gateway. This replaces
intent decision 3, and needs the owner's OK:

- one HFP gateway: it is used;
- several: a **phone pick** card lists the gateways by alias first, and
  everything after it (lookup, pick, confirm) runs against the chosen
  gateway;
- none: "Your phone isn't connected over Bluetooth."

Caller names come only from the phonebook of the phone carrying that
call, through the call's own gateway address (`h["ag"]`). A Flux-only
call keeps Flux's caller name and does no lookup.

### 4. The handset name (`Call.sync`, `app/server.py:8085-8196`)

- The row keeps two identities:
  - `phone_who`: today's `who`, the Flux caller name or the HFP `Name`;
  - `who`: what the handset shows.
- **Lookup** runs only for a call with an HFP leg, and only with the
  **HFP leg's own number**, `h["number"]`. It never uses a number taken
  from a Flux leg the call was matched with.
  - If `phone_who` is empty, or is a bare number (only digits once `+`,
    spaces, dashes, dots and brackets are stripped), `who` becomes
    `Pbap.name_for(address, h["number"])` when that hits, and a new field
    `label` holds the number's label.
  - If `phone_who` is a real name, it is kept, and `label` is added only
    on a unique phonebook match for that number.
  - With a withheld or missing HFP number, or no hit, the display is as
    today: the number, or "Unknown caller".
- **The cache is never waited on.** When the cache is `cold`, `sync`
  starts one background load. `Call.sync()` runs again only if that load
  finishes `ready` under the same generation. Failures are cached
  (Design 1), so there is no loop.
- `label` is added to the key lists in both `_emit` (`:8032`) and
  `current_event` (`:8063`), so a fresh or reconnected page shows the
  same identity.
- The handset shows `who`, plus `· label` (localised) when present, in
  both the display (`HS.text`, `index.html:3708`) and the bar pill.
- **Privacy:**
  - the spoken ring announcement (`phone_on_call`, `:8344`) and the
    missed-call callback (`on_missed`, `:8135`) get `phone_who`, never
    the phonebook `who`;
  - `PHONE_MISSED` cards and anything read aloud never carry a phonebook
    name, because Nixi's voice is ElevenLabs (cloud).

### 5. Outgoing call states (`Call.sync`)

These rules apply only to HFP-backed calls. A Flux-only `talking` call
behaves as today.

- HFP `dialing` and `alerting` give `phase` `"dialing"`, `path` `"host"`,
  `keys` `["hangup"]` and `answered_at` `None`. A new row flag
  `hfp_outgoing` is set.
- `phase` `"active"`, with `answered_at`, starts only on HFP `active`.
- Ending:
  - the `ended` rule (`:8128-8129`) also covers `old["phase"] ==
    "dialing"`, for the same HFP path, going `disconnected`. That covers
    a cancel before answer and no answer, and both show "Call ended" for
    2 s;
  - `hfp_incoming` stays false, so `call_missed` never fires for an
    outgoing call.
- The existing second-call rule (`second` gives `keys = []`) still
  overrides. If a second call appears while dialing, the handset shows
  "Second call: use your phone".
- `Ambient.phone_call` follows `Hfp.any_call()` as today.
- The handset shows "Calling…" (`call.dialing`) with hang-up and the
  phone icon.

### 6. "Call …": voice and typed (`app/quick.py`, `app/server.py`)

**What belongs to telephony** is decided by the phrase alone, not by
Phone state or by whether the target is valid:

- English `call <x>`, `phone <x>`, `ring up <x>` and `dial <x>`, plus the
  `nb` and `pl` lists in the locale phrase files;
- `<x>` is a number-like string (digits, `+ * # ( ) - .` and spaces), or
  one to four words;
- excluded, so the phrase falls through to the agent as today:
  - `<x>` starts with a stop word: `the`, `that`, `this`, `a`, `an`,
    `it`, `me`, `us`, `them`, or a code word (`function`, `method`,
    `api`, `script`, `endpoint`, `hook`), plus the `nb`/`pl` lists in
    the locale files;
  - `<x>` is a phrase the existing phone matchers own. `phone_find` and
    the other phone phrases are checked first, so "ring my phone" stays
    find-my-phone, and "call me at 5" stays the timer.
- `quick.py` only classifies, and has no side effects. It returns
  `{"phone": {"do": "call", "target": x}}`.

**`phone_quick` handles `do == "call"`** before its `Phone.connected`
gate, because calling needs only Bluetooth. Every outcome is a handled
reply, never `None`, so a call phrase never reaches the agent. **Replies
never repeat `<x>` or a number.**

| Case | Reply / card |
|---|---|
| Phone off | the existing `phone.off` |
| Desktop locked | `phone.call_locked`: "Unlock your computer to make calls." |
| A call already showing or in progress, or a dial pending | `phone.call_busy` |
| No gateway | `phone.call_no_bt` |
| Several gateways | the phone pick card, then the rows below for that gateway |
| `<x>` number-like but not allowed (Design 8) | `phone.call_not_allowed` or `phone.call_short` |
| `<x>` an allowed number | the confirm card |
| `<x>` a name, cache `cold` or `loading` | `phone.call_loading`, then the result as a card or a short local message |
| cache `sharing` | `phone.call_sharing_off`: "Turn on Contact sharing for this computer in your phone's Bluetooth settings." |
| cache `unreachable` or `failed` | `phone.call_lookup_failed` |
| 0 matches | `phone.call_not_found`: "I couldn't find that contact." |
| one person, one dialable number | the confirm card |
| otherwise | the pick card: one row per person and number, with name, label and a masked number (`…1234`) |

Voice and typed requests take the same path. Like other local quick
replies, only the reply text enters history. The utterance itself is
handled as today's phone phrases are.

### 7. Cards, tokens and the dial (`app/server.py`, `app/static/index.html`)

**Stage kinds:**
- `phone_call_gateway`, `phone_call_pick` and `phone_call_confirm`;
- all three are added to `phone_on_screen()` (`:7802`);
- they are removed from the stage when the desktop locks, Phone is
  turned off, the gateway disconnects, or a newer call request replaces
  them.

**Server-side state, under `PHONE_LOCK`:**
- `PHONE_CALL`: the one live request,
  `{id, gen, gateway_path, address, created, rows: {token: (name, label, number)}, confirm: id|None}`;
- a new request replaces the old one. All tokens are bound to its `id`,
  to `PHONE_GEN`, and to a 60 s expiry. `PHONE_GEN` is bumped on lock,
  Phone off and gateway loss, as for SMS drafts;
- `DIAL_PENDING`: `{gateway_path, number, since}`. It is set when a
  confirm is consumed, and blocks any new request or confirm. It is
  cleared when HFP reports a call on that gateway, or after 30 s with no
  call, or at once on a definite failure (`busy`/`gone`). An `unknown`
  result keeps it until a call appears or the 30 s pass, so a lost reply
  cannot lead to a second dial.

**What the page gets:** display fields (name, label, masked or full
number) for showing only, plus opaque tokens. The endpoints accept only
tokens.

**Endpoints,** each requiring `click_ok(X-Nixi-Click)` (403 otherwise):

- `POST /api/phone/call-gateway {token}`: runs the lookup for that
  gateway, and its result follows the table above.
- `POST /api/phone/call-pick {token}`: turns that row into the confirm
  card (`PHONE_CALL.confirm`). It never dials.
- `POST /api/phone/dial {token}`:
  1. First, without `PHONE_LOCK`, it checks `Call.visible()` and
     `Hfp.any_call()`. This keeps the lock order `Call.lock` before
     `PHONE_LOCK`, the same order `Call.sync` uses, so there is no
     inversion.
  2. Then, under `PHONE_LOCK`, it checks the token against
     `PHONE_CALL.confirm`, the 60 s expiry and `PHONE_GEN`, that Phone is
     on and the desktop unlocked, that the gateway is present with the
     same address, and that no `DIAL_PENDING` is set. It then consumes
     the confirm and sets `DIAL_PENDING`.
  3. It calls `Hfp.dial` once, outside the lock. `Hfp.dial`'s own
     `any_call()` check is the last guard.
  The reply is `{"ok", "say"}`, using `phone.call_failed` or
  `phone.call_stale`. A failure never brings the confirm back.

**Page side:** the card buttons follow `stagePhoneDraft`
(`index.html:3419`). They act only for
`e.isTrusted && ['mouse','pen','touch'].includes(e.pointerType)` and send
`CLICKKEY.hdr()`. Enter or Space does nothing.

### 8. Allowed numbers

The same rule applies to typed numbers and to contact numbers.

- **Normalise:** strip `tel:`, spaces (including Unicode spaces),
  dashes (including en and em dashes), dots and brackets.
- **Allowed:** `+?[0-9]{6,15}`.
- **Refused:** anything with `*`, `#`, `,`, `;`, `p` or `w`, which covers
  MMI, USSD and post-dial strings (`phone.call_not_allowed`); and 1 to
  5 digits, which covers emergency, voicemail and short codes such as
  `112`, `911`, `999`, `110` and `113` (`phone.call_short`: "For
  emergency or short numbers, use your phone.").

A digits-only rule cannot tell a premium-rate or foreign number from any
other. This change does not try to. The confirm card always shows the
full number before the click.

### 9. Locale

New keys in `app/lang/en.json`, `nb.json` and `pl.json`, with the
existing English fallback:

- `call.dialing`, and `call.label_mobile`, `call.label_home`,
  `call.label_work`, `call.label_other`;
- `phone.call_locked`, `phone.call_busy`, `phone.call_no_bt`;
- `phone.call_not_allowed`, `phone.call_short`, `phone.call_loading`;
- `phone.call_sharing_off`, `phone.call_lookup_failed`,
  `phone.call_not_found`;
- `phone.call_failed`, `phone.call_stale`;
- `phone.call_gateway_title`, `phone.call_pick_title`,
  `phone.call_confirm_title`, `phone.call_button`;
- the phrase lists `phone_call` and `phone_call_stop`.

Phone off reuses the existing `phone.off`.

## Alternatives rejected

- **Flux `call.dial` with `CALL_PHONE`.** It needs Android and daemon
  changes and a runtime grant, and runs into background-start limits.
  The audio would stay on the phone.
- **adb `am start -a android.intent.action.CALL`.** Wireless debugging
  went offline in the check, and it gives Nixi a full device shell.
- **Flux `contacts.search`.** Needs Flux, APK and IPC changes. It stays
  as the fallback (intent decision 1).
- **PBAP `Search` per lookup.** Each incoming call would open a new OBEX
  session. The 10-minute cache was approved.
- **Matching numbers by the last 8 digits only.** Collisions would show
  the wrong person. A suffix is used only when it is unique.
- **Speaking phonebook names.** It would send contact names to a cloud
  voice.
- **Dialing from voice on a single match.** Rejected by the intent.

## Risks

- **PBAP authorisation:** until the Pixel allows contact sharing for the
  host, names don't appear and "call <name>" says to turn it on. Typed
  numbers still work.
- **Unverified live behaviour:** the `Dial` reply shape, obexd's exact
  error names, and the SCO timing (ringback on the host) are checked on
  hardware.
- **Large address books:** the first `PullAll` can take seconds. It runs
  off the request thread, and the name fills in when it is ready.
- **The vCard transfer file** exists briefly in a private runtime
  directory. It is deleted in `finally`, and stale ones at startup.
- **Intent decision 3 is replaced** by the gateway pick (Design 3).
  This needs the owner's OK.
- **The phrase boundary** can take something meant for the agent ("call
  Bob"). Replies say what Nixi did, and the stop-word lists keep the
  common code phrases out.
- **Many voicemail numbers are short codes,** which this rule refuses.
  The hardware check uses a saved harmless contact with a full number.

## Verification

**Unit tests**, using fakes only, never a real phone, Bluetooth, adb or
contacts:

- **`tests/test_pbap.py`** (synthetic vCards):
  - parsing: `FN`/`N` fallback, labels, `tel:`, Unicode dashes, and
    non-dialable numbers;
  - search order and accents, and the 8-match limit;
  - `name_for`: an exact key, a unique suffix, a suffix collision
    (`None`), and duplicate contacts;
  - the transfer: `Status` already `complete` from `PullAll`, completion
    after subscribe, `error`, and a timeout that calls `Cancel`, with the
    file and directory removed in each case;
  - error mapping (`sharing`, `unreachable`, `failed`), and the failure
    backoff;
  - a generation bump during a load discards the result;
  - the 10-minute expiry, and one load per address;
  - startup cleanup.
- **`tests/test_hfp*.py`:**
  - `dial()` reaches `AudioGateway1.Dial` on the right path with one
    string;
  - `busy`, `gone` and `unknown`;
  - `gateway_list()`: the system-bus alias, the fallback, and duplicate
    aliases.
- **`Call.sync`:**
  - `dialing` → `alerting` → `active` → `disconnected`: the phase, keys,
    `answered_at`, and "Call ended";
  - cancel before answer: "Call ended" and no missed call;
  - a second call during dialing gives empty keys;
  - a Flux-only `talking` call is unchanged, with Flux online, and an
    incoming regression with Flux online;
  - incoming with a number only: a warm cache gives the name and label;
    a cold cache gives the number first, then the name after one load;
    with sharing off, no loop;
  - a withheld HFP number alongside an unrelated Flux leg shows no
    phonebook name;
  - a real phone-sent name is kept, and a formatted bare number counts
    as a number;
  - `label` is present in both `_emit` and `current_event`;
  - the ring announcement and the missed callback receive only
    `phone_who`.
- **Quick and `phone_quick`:**
  - every row of the table in Design 6;
  - "call that function", "call me at 5" and "ring my phone" fall
    through as today;
  - "call Anna", "dial *#06#" and "call 112" are handled locally;
  - one `nb` and one `pl` phrase, plus the English fallback;
  - no reply contains `<x>` or a full number.
- **Endpoints:**
  - 403 without the click key;
  - a replayed, expired, or replaced token (two requests: only the
    newest works);
  - a gateway pick, then lookup on that gateway;
  - a stale pick after lock, Phone off, or disconnect;
  - two confirms clicked before the first HFP event: one dial;
  - an `unknown` dial result keeps `DIAL_PENDING`;
  - a missed call that lands during `/api/phone/dial` causes no
    deadlock (a thread-ordering test);
  - `Hfp.dial` is called at most once.
- **Page** (`stages_fit.mjs` fixtures):
  - the three cards fit;
  - the buttons ignore Enter, Space and untrusted clicks;
  - the handset shows "Calling…" with hang-up, and `who · label`, in
    both the display and the pill.
- **Regression:** the full suite.

**On hardware**, on p620 with the owner present:

1. Turn on Contact sharing for p620 on the Pixel.
2. An incoming call from a saved contact shows its name and label.
3. "Call <a harmless saved contact with a full number>": pick if
   needed, confirm, click, "Calling…", the host mic and speaker work,
   then hang up before or after answer.
4. A typed full number works the same way.
5. "call 112" is refused locally.
6. With Bluetooth off, the right message appears.

razer is checked the same way once the Pixel is paired with it.
