# Spec: accept an ElevenLabs key from sops-nix

## Design

### 1. `app/eleven.py`

The allowed roots move out of `_key()` (`:37`) into a module constant, so tests can point them at a temporary layout:

```python
KEY_ROOTS = ("/run/agenix", "/run/agenix.d", "/run/secrets", "/run/secrets.d")   # agenix, sops-nix (NixOS module)
```

`_key()` starts from a fresh list, `roots = list(KEY_ROOTS)`, and appends `$CREDENTIALS_DIRECTORY` as it does today
(`:38-39`). The `KEY_ROOTS` entries are **not** resolved with `realpath`: a root that is itself a link must not widen
what is accepted. Nothing else changes:

- `realpath` of the configured file (`:36`), then the root check (`:40`)
- the no-follow `os.open` of the resolved path (`:43`)
- the `fstat` checks: regular file, 1–256 bytes, owner root or the user (`:45-46`)
- the key regex (`:49`)
- no key text in any error

**The sops-nix layout:** in the NixOS module's default layout, `/run/secrets` is a directory link to
`/run/secrets.d/<gen>`, and each secret is a regular file inside it. So `realpath` of `/run/secrets/<name>` is
`/run/secrets.d/<gen>/<name>`, and the root check needs exactly this one addition. A link that resolves outside the
roots, such as into `/home/...` or `/nix/store`, is still refused, because the check runs on the resolved path.

**What the check relies on:** `O_NOFOLLOW` guards only the last path component. Containment also relies on every
directory from `/run` down to the secret being owned by root and not writable by Nixi's user, which holds for agenix
and the sops-nix NixOS module. That is why the user-writable Home Manager location stays out of scope.

**A generation switch during a read:** if sops-nix re-points `/run/secrets` and removes the old generation between
`realpath` and `os.open`, that one call fails as "no key" and the next one reads the new generation. This is accepted:
switches happen only on activation, and Nixi reads the key per request.

### 2. `docs/GUIDE.md` (the key section, `:307-327`)

- **The rule line** (`:311`) lists `/run/secrets.d` too.
- **A sops-nix example** goes next to the agenix one. It extends an existing sops-nix setup: `sops.defaultSopsFile`
  (or a `sopsFile`) already holds a key `api-elevenlabs` whose value is the raw API key.

  ```nix
  {
    # sops-nix (NixOS module) -> /run/secrets/api-elevenlabs, a file in /run/secrets.d/<generation>/
    sops.secrets.api-elevenlabs = {
      owner = "<your-user>";        # sops-nix defaults to root:root 0400, which he can't read
    };
  }
  ```

  It also says to set `"eleven_key_file": "/run/secrets/api-elevenlabs"` in `~/.config/nixi-companion/config.json`.
  It names the supported layout: the default `/run/secrets` mount. `neededForUsers` secrets
  (`/run/secrets-for-users.d`) and a custom mount point aren't accepted.
- **The "not supported yet" line** (`:327`) is replaced with one sentence: the Home Manager sops-nix module, whose
  secrets live under the user runtime dir, isn't supported.

### 3. `tests/test_eleven.py`

A new test, `test_key_from_sops_layout`, next to `test_key_symlink_and_rejections` (`:61`):

- **The real roots:** it first asserts the unpatched `eleven.KEY_ROOTS` equals the four roots above, so the test
  fails if `/run/secrets.d` is dropped or an agenix root goes missing.
- **Setup:** the layout is built under `Path(os.path.realpath(self.tmp.name))`, because the roots aren't resolved
  and `$TMPDIR` may be a link. It patches with `mock.patch.object(eleven, "KEY_ROOTS", (<tmp>/secrets,
  <tmp>/secrets.d))` and clears `CREDENTIALS_DIRECTORY` with `mock.patch.dict`, as the existing test does (`:74`).
- **Read:** `secrets.d/1/api-elevenlabs` holds the key, `secrets` → `secrets.d/1`, and `eleven_key_file` is
  `secrets/api-elevenlabs`. Expect `_key()` == key.
- **Generation switch:** `secrets.d/2/api-elevenlabs` holds a new key, and `secrets` is replaced (unlink, then link)
  to point at `secrets.d/2`. Expect the new key.
- **Escapes:** `secrets.d/2/api-elevenlabs` becomes a link to a file outside the roots, then to a sibling-prefix path
  `secrets.d-evil/key`. Expect `has_key()` is False for both.

## Alternatives rejected

- **Allowing all of `/run`:** too broad. Any service's runtime file would pass.
- **Not resolving symlinks, and checking the configured path:** a link could then point anywhere. The resolved-path
  check is the point.
- **Accepting only `/run/secrets.d/<digits>/`:** it would also refuse sops-nix's own `/run/secrets.d/age-keys.txt`.
  That file is root's, mode `0400`, so Nixi's user can't open it anyway. The extra pattern isn't worth it.
- **Opening relative to a root directory fd (`openat` per component), for race-proof containment:** it changes the
  checks the intent keeps as they are. The root-owned directories make it unnecessary here.
- **Supporting Home Manager sops-nix (`$XDG_RUNTIME_DIR/secrets.d`) now:** out of scope per the intent. That
  directory is writable by the user, so the check above wouldn't hold.

## Risks

- **None for agenix users:** the same roots are still accepted.
- **Group-shared secrets:** a secret owned by another service user is refused by the owner check, even if Nixi's user
  can read it through its group. This is the current rule; the GUIDE example sets the owner.
- `tests/test_docs_names.py` (#217) checks names in the docs. The GUIDE edit keeps the option names
  (`eleven_key_file`) unchanged.
