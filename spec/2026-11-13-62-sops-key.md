# Spec: accept an ElevenLabs key from sops-nix

## Design

### 1. `app/eleven.py`

The allowed roots move out of `_key()` (`:37-40`) into a module constant, so tests can point them at a temporary
layout:

```python
KEY_ROOTS = ("/run/agenix", "/run/agenix.d", "/run/secrets", "/run/secrets.d")   # agenix, sops-nix (NixOS module)
```

`_key()` builds its list from `KEY_ROOTS` and adds `$CREDENTIALS_DIRECTORY` as it does today. Nothing else changes:

- `realpath`, then the root check
- the no-follow `os.open` of the resolved path (`:42`)
- the `fstat` checks: regular file, 1–256 bytes, owner root or the user (`:44-46`)
- the key regex (`:48`)
- no key text in any error

`/run/secrets.d` is the sops-nix NixOS module's generation root: `/run/secrets` links to `/run/secrets.d/<gen>`, and
each secret links into it. The root check needs exactly this one addition. A file in another directory that a link
points at, such as `/home/...` or `/nix/store`, is still refused, because the check runs on the resolved path.

### 2. `docs/GUIDE.md` (the key section, `:309-327`)

- **The rule line** (`:311`) lists `/run/secrets.d` too.
- **A sops-nix example** goes next to the agenix one. It names the two requirements, the owner and the path:

  ```nix
  {
    # sops-nix (NixOS module) -> /run/secrets/api-elevenlabs, resolving into /run/secrets.d/<generation>/
    sops.secrets.api-elevenlabs = {
      owner = "<your-user>";        # sops-nix defaults to root:root 0400, which Nixi can't read
    };
  }
  ```

  It also says to set `"eleven_key_file": "/run/secrets/api-elevenlabs"` in `~/.config/nixi-companion/config.json`.
- **The "not supported yet" line** (`:327`) is replaced with one sentence: the Home Manager sops-nix module, whose
  secrets live under the user runtime dir, isn't supported.

### 3. `tests/test_eleven.py`

A new test, `test_key_from_sops_layout`, next to `test_key_symlink_and_rejections` (`:61`). It builds the sops-nix
layout under a temp dir and patches `eleven.KEY_ROOTS` to that dir's `secrets` and `secrets.d` paths:

- `secrets.d/1/api-elevenlabs` holds the key, `secrets` → `secrets.d/1`, and `eleven_key_file` is
  `secrets/api-elevenlabs`. Expect `_key()` == key.
- **Generation switch:** `secrets.d/2/api-elevenlabs` holds a new key, and `secrets` is re-pointed to `secrets.d/2`.
  Expect the new key.
- **Escape:** `secrets.d/2/api-elevenlabs` becomes a link to a file outside the roots. Expect `has_key()` is False.

## Alternatives rejected

- **Allowing all of `/run`:** too broad. Any service's runtime file would pass.
- **Not resolving symlinks, and checking the configured path:** a link could then point anywhere. The resolved-path
  check is the point.
- **Supporting Home Manager sops-nix (`$XDG_RUNTIME_DIR/secrets.d`) now:** out of scope per the intent. The user
  runtime dir is writable by the user, which needs its own reasoning.

## Risks

- **None for agenix users:** the same roots are still accepted.
- `tests/test_docs_names.py` (#217) checks names in the docs. The GUIDE edit keeps the option names
  (`eleven_key_file`) unchanged.
