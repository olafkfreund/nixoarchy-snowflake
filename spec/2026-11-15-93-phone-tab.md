# Spec: Settings gets a Phone tab of its own

## What the measurements show

These were measured in headless Chromium with `--disable-gpu`, using the `settings_fit` harness and a throwaway probe.
The probe clones the More button as a sixth "Phone" tab before More, then measures each tab at three Settings widths.
"Spare" is the button's width minus the icon (14 px), the gap (5 px) and the label. Every label stayed on one line,
and no button overflowed.

**p620's font (`Inter` resolves to Liberation Sans):**

| Settings width | Tabs | Tab width | Spare for "Plugins" (the tightest) | Spare for "Phone" |
| --- | --- | --- | --- | --- |
| 420 (minimum) | 5 | 77.6 | 19.3 | — |
| 420 (minimum) | 6 | 64.7 | **6.3** | 11.0 |
| 480 | 6 | 74.7 | 16.3 | 21.0 |
| 560 (default) | 6 | 88.0 | 29.6 | 34.3 |

**DejaVu only** (a test-only `FONTCONFIG_FILE`, `dejavu-fonts-2.37` from the flake's nixpkgs), the wider font that
other machines and CI may use:

| Settings width | Tabs | Spare for "Plugins" | Spare for "Phone" |
| --- | --- | --- | --- |
| 420 | 5 | 12.6 | — |
| 420 | 6 | **0**: the button grows from 64.6 to 65 px to fit | 7.6 |

So six tabs fit at the default size, 560 px (`setDefaultSize()`, `index.html:3694`), with room to spare. At the
minimum size, "Plugins" touches its edges with DejaVu and has 6 px with Liberation. That's too tight to promise.

## Design

### 1. The tab and its panel (`app/static/index.html`)

- **The button:** add it after Plugins (`:882`) and before More (`:883`), following the same pattern:
  `id="tab-phone"`, `role="tab"`, `aria-selected="false"`, `aria-controls="panel-phone"`, `tabindex="-1"`,
  `data-tab="phone"`. Use a phone icon in the same stroke style:
  `<svg viewBox="0 0 24 24"><rect x="7" y="2.5" width="10" height="19" rx="2.2"/><path d="M11 18.5h2"/></svg>`.
  The label is `Phone`.
- **The panel:** add `<div class="tab" id="panel-phone" role="tabpanel" aria-labelledby="tab-phone" data-tab="phone">`
  between the Plugins panel and the `MORE` comment (`:1023-1024`). It gets a `<!-- ===== PHONE ===== -->` comment like
  the others.
- **The row moves:** the whole `#phoneRow` block (`:936-937`, holding `#phoneSw` and `#phoneStat`) moves from Look into
  the Phone panel unchanged. Its IDs stay, so `renderPhone()` (`:4154`) and the switch's handler keep working.
- **`TABS`** (`:4040`) becomes `['look','voice','brain','plugins','phone','more']`. `showTab()` checks against it, so
  `phone` becomes a valid remembered tab and unknown values still fall back to Look.
- **The indicator and the keyboard follow on their own:**
  - `moveInd()` (`:4071`) sizes the indicator from the selected button's own `offsetWidth`/`offsetLeft`.
  - The keyboard handler (`:4078-4084`) steps through `TABS`, not the buttons. So `TABS` must list the tabs in
    the same order as the buttons. Section 8's new check compares the two orders.
- **The switch keeps working from its new tab:** its handler is delegated from the whole Settings panel
  (`setEl.addEventListener('change',…)`, `:4533`, then `phoneSw` at `:4562`).

### 2. Room for six tabs at narrow widths (`app/static/index.html`, the tab CSS at `:613-616`)

When the tab bar is too narrow for every icon and label, the icons hide and the labels stay:

```css
#tabs{container-type:inline-size}
@container (width < 414px){ #tabs button svg{display:none} }
```

- **The threshold:** a container query measures the bar's *content* box. That is its outer width minus its 3 px
  padding on each side, so 6 px less (Codex, agy review).
  - With DejaVu, "Plugins" needs 14 + 5 + 46 = 65 px with its icon. Keeping 4 px spare needs a 69 px tab. Six of
    those make 414 px of content, which is a 420 px bar and a Settings window of 446 px.
  - So icons show from a 446 px window up, and hide below that.
  - At 420 px with icons hidden, the flex `gap` no longer applies (only the label is left). "Plugins" then has about
    19 px spare with DejaVu (64.6 − 46).
- **What users see:**
  - At the default size and anything down to 446 px, nothing changes: icon and label, as now.
  - Only a Settings window resized narrower shows labels alone.
- **Labels stay** because they say what each tab is. The icons only decorate. Each button keeps its text, so ARIA
  names don't change.
- **Why a container query:** Settings changes width through `--setW`, independently of the viewport, so a media query
  can't see it. The query only follows the bar's layout width. `fit()` scales by transform, which doesn't change it.
  A seventh tab would need a new threshold. WebKitGTK 2.54 (p620) and current Chromium support container queries.
  Nothing in the file uses one yet, so this is the first.

### 3. The indicator follows a Settings resize (`app/static/index.html:4042-4043`)

`moveInd()` runs when a tab is chosen, when Settings opens, and on the window's `resize` event (`:4668`). In the real
window a Settings resize usually resizes the window, which fires that event. It doesn't when the window size stays the
same, and never in the headless test. So `setResize`'s frame callback also calls `moveInd()`:
`requestAnimationFrame(()=>{ setResizeFrame=0; sizeWindow(); sendRegion(true); moveInd(); })`.

    - Set the viewport to 900 × 800 so `fitK` is 1 and every measurement is in plain layout pixels.

      past the indicator's 450 ms transition.
  - **At Settings widths 420, 445, 446 and 560, for every tab:**

## Alternatives rejected

- **A smaller gap or padding:** with DejaVu, "Plugins" would gain only about 1 px at 420 px. That isn't enough.
- **A smaller font for all tabs:** it changes the look at every size to fix the narrowest one.
- **Icons only, hiding the labels:** icons alone don't say "Plugins" or "More" clearly, and the labels carry the names.
- **Scrolling or wrapping the tab bar:** it breaks the sliding indicator and the one-row look.
- **Raising the minimum Settings width:** it changes the resize limits that `settings_fit` already pins (#175), for
  one tab.
- **A shorter label, "Apps" instead of "Plugins":** it renames a feature to fix a layout.

## Risks

- **The container query is new to this file.** If WebKitGTK didn't apply it, the narrow case would look like the
  measurement without the fix: tight but on one line. The by-eye check on p620 covers it.
- **`container-type:inline-size` on `#tabs`:** the bar's width comes from its parent (it's a block child with
  margins), never from its content, so containment can't shrink it. The new fit section checks the bar is 534 px at
  560.
- **The extra `moveInd()` in `setResize`:** during a drag it runs once per frame at most, since `setResize` already
  coalesces into one frame. The indicator already animates its moves, so a resize now slides it into place.
- **CI fonts:** the fit test runs with whatever fonts CI has. Measured with DejaVu and Liberation, both pass with the
  design. A font wider still could fail the 2 px check, which is the point of the check.
- **Session tab memory:** someone whose saved tab is `more` still opens More. Nobody has a saved `phone` yet.
