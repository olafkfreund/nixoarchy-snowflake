# Spec: CI for nixoarchy-snowflake

## What the probe measured

A throwaway workflow on branch `ci-probe/63` (never merged) ran on `ubuntu-latest` (Ubuntu 24.04, 4 vCPU), run
`43568839355`:

- **The sandbox tests can run.** Ubuntu sets `kernel.apparmor_restrict_unprivileged_userns = 1`, which blocks `bwrap`.
  After `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`, one more thing failed: the sandbox binds only
  `/nix/store`, and a plugin's `#!/usr/bin/env` line needs an `env` there. Bind-mounting Nix coreutils' `env` over
  `/usr/bin/env` (as on NixOS) fixed it: `test_plugin_sandbox.py` ran 37 tests, 0 skipped, in 6 s.
- **Setup is cheap:** checkout and Nix install take 4 s, the sysctl and the bind mount 21 s, `nix build` cold 21 s.
  `nix flake check` takes 33 s on p620.
- **The whole suite, file by file, serially: 43 min.** It splits like this:

  | Group | Files | Time |
  | --- | --- | --- |
  | Unit tests (not `*_fit`) | 73 | 153 s |
  | Browser fit tests, except the two below | 14 | 698 s |
  | `test_character_fit` + `test_accessories_fit` | 2 | 1008 s + 719 s |

- **83 of 89 files passed.** The other six:

  | File | Cause | Spec decision |
  | --- | --- | --- |
  | `test_sessions.py` | `test_send_needs_an_exact_match` (`:143`) doesn't mock `herdr_read`: on p620 it reads a **live herdr pane**; on the runner there is none | Fix the test (a leak to the live system) |
  | `test_mail.py` | 5 Hear tests rely on `Speaker.available()` (`app/server.py:6784`), which checks the host's audio | Fix the tests: mock `Speaker.available` |
  | `test_mirror_fit.py` | "idle shrinks after off" waits a fixed 1.5 s (`tests/mirror_fit.mjs:35`); too short on the runner | Fix: wait for the class, up to 6 s |
  | `test_character_fit.py` | "plug:fixture: skin halo fits 340 × 460", bounds `8,3,330,326`: the top edge rounds to 3 but is below it | See step 6 of the design |
  | `test_bridge.py` | 4 skips: no `NIXI_SRC` | Allowed skip |
  | `test_window_webkit.py` | 1 skip: no Wayland | Allowed skip |

## Design

### 1. `.github/ci/run_tests.py`: the runner (new, about 100 lines, prototyped in the probe)

```bash
python3 -B .github/ci/run_tests.py [--deadline S] [--allow FILE] [--exclude NAME]... [--tests DIR] [PATTERN...]
```

- **One process per file:** it starts itself as a child per `tests/test_*.py` (`--child FILE REPORT`), which runs
  `unittest` discovery for that one file with `verbosity=2`. `unittest` exits 0 on a skip, so the child writes
  `result.skipped` as JSON (test id, reason). Parsing the text output was tried and failed: reasons can be quoted
  either way, and tests print on the same line.
- **A child with no tests run fails.** Seven files have no `unittest.main()` (`test_agent_approvals.py` and others),
  so `python3 tests/x.py` would run nothing; discovery runs them all.
- **Deadline:** each file runs in its own session (`start_new_session=True`) with a deadline, 300 s by default. When
  it ends, for any reason, the runner kills the whole process group, so servers and browsers die with it. A timeout
  is `TIMEOUT`, a failure.
- **Skips:** each skip is printed with its id (`file::Class.test`) and reason. A skip not in the allow-list fails
  the file (`SKIP?`).
- **Output:** one line per file (state, seconds, skip count), and the full output in a collapsed `::group::` for any
  file that didn't pass. The last line counts the passed files; the exit code is 1 if any file didn't pass.
- `--exclude NAME` (repeatable) leaves a file out, so the two jobs split the suite. `--tests DIR` points it at another
  test folder, for its own test.

### 2. `.github/ci/skips.txt`: the allow-list (new)

One entry per line, `file::Class.test  # reason`; an entry without a reason is an error.

```text
test_bridge.py::BridgeTest.test_1_text_streams_as_delta  # needs the nixi-nixarchy bridge checkout (NIXI_SRC)
test_bridge.py::BridgeTest.test_2_permission_yes_sends_allow_once  # (same)
test_bridge.py::BridgeTest.test_3_stop_proc_cancels_turn  # (same)
test_bridge.py::BridgeTest.test_4_dead_bridge_restarts_on_next_prompt  # (same)
test_window_webkit.py::WebKitTokenScript.test_right_port_only  # needs a Wayland session; GitHub runners have none
```

The other skip sources the intent lists are provided instead:

- **Chromium, Node, ffmpeg** from Nix (section 3)
- **`origin/main` for the character baseline:** `fetch-depth: 0`
- **`NIXI_DOCS_ALL=1`:** a missing doc fails

### 3. `flake.nix`: a `ci` dev shell

`devShells.<system>.ci` = the default shell's packages plus `chromium`, `nodejs` and `ffmpeg`, with
`NIXI_SANDBOX_TESTS = "require"` and `NIXI_DOCS_ALL = "1"`. Everything comes from the flake's locked nixpkgs, not
`nixpkgs#` from the registry, so CI uses the same versions every run. The default shell stays small for local sandbox
runs.

### 4. `.github/workflows/ci.yml` (new)

- **Triggers:** `push` to `main`, `pull_request`, `workflow_dispatch`.
- `permissions: contents: read`.
- `concurrency` with `cancel-in-progress`.
- **Actions pinned by commit**, the same pins as nixi-nixarchy's CI:
  - `actions/checkout@3d3c42e5…` (v7.0.1), with `fetch-depth: 0`
  - `cachix/install-nix-action@52611812…` (v31.3.0)
- **Two jobs on `ubuntu-latest`, side by side.** The repo is public, so runner minutes are free.
  - **`test`** (`timeout-minutes: 40`):
    1. the sysctl and the `env` bind mount
    2. `nix flake check -L` (the build and the `checks`)
    3. `nix develop .#ci -c python3 -B .github/ci/run_tests.py --exclude test_character_fit.py --exclude
       test_accessories_fit.py`

    Expected about 15 min.
  - **`fit-slow`** (`timeout-minutes: 60`): the same setup, then the runner on `test_character_fit.py` and
    `test_accessories_fit.py` with a 1800 s deadline each (measured 1008 s and 719 s). Expected about 30 min.
- The sysctl step carries a comment: it relaxes a runner-only restriction so `bwrap` can make user namespaces, and
  touches no host of ours.

### 5. Test fixes the probe found

- `tests/test_sessions.py:139-143`: patch `s.herdr_read` to return a fixed pane text. The test then checks what it
  means to, and never reads a live herdr pane.
- `tests/test_mail.py`, the 5 Hear tests (`:341` and the others that assert `say` was called): patch
  `s.Speaker.available` to return `True`.
- `tests/mirror_fit.mjs:35-36`: replace the fixed `MS(..., 1500)` wait before the `peek` check with a loop that polls
  every 100 ms for up to 6 s.

### 6. `test_character_fit`'s halo check

**Pending:** the run on p620 is still going. If the halo fails there too, it is a real overflow, and it gets its own
issue and is fixed before this PR merges. If it passes on p620, the 3 px edge is met only on fast frames, and
the check samples a frame later on the runner. The fix is then in the test: sample after the animation settles, never
a looser bound.

## Alternatives rejected

- **The whole suite in one job:** 43 min per PR.
- **The two slow fit tests only on `main`:** PRs that change the character would merge before the check runs.
- **Running files in parallel in one job:** the fit tests are timing-sensitive (`test_mirror_fit` already failed
  serially on the runner), and 4 vCPUs shared with Chromium would make that worse.
- **`nixpkgs#chromium` from the registry:** unpinned, so a run could change with no change in the repo.
- **Ubuntu's Python or Chromium:** the sandbox runs `sys.executable` inside a `/nix/store`-only bind, and Ubuntu's
  `chromium-browser` is a Snap that won't start with `HOME` redirected.
- **Checking out nixi-nixarchy for `test_bridge`:** it would add a second repo and `npm ci`, and nixi-nixarchy's own
  CI runs its bridge tests. It stays an allowed skip.
- **A self-hosted runner** for user namespaces: not needed, since the sysctl works.
- **`magic-nix-cache`:** the setup takes under 30 s; a cache adds an action for little.

## Risks

- **GitHub changes the runner image** (the sysctl name or the AppArmor policy): the sandbox step fails loudly, never
  silently, because the tests run in require mode.
- **Timing flakes in the fit tests** on a slow runner. The deadlines leave room (300 s against at most 168 s
  measured). A flaky check gets fixed in the test (wait for a condition), never by a retry loop.
- **No host is touched:** the workflow runs only on GitHub's runners. Branch protection stays the owner's choice.

## Verification

- `python3 -B tests/test_ci_runner.py`: the runner's own test, with a temp test folder. It checks four cases: a
  passing file, a failing file, a skip not on the list (fails), and a sleep past a 2 s deadline (`TIMEOUT`, with its
  child process gone).
- The PR's own run: both jobs green, the per-file table in the log, and the skips shown as `allowed`.
- A deliberate red run on the PR branch: a commit that removes one `skips.txt` entry shows `SKIP?` and fails. It is
  reverted before merge.
- After merging: delete branch `ci-probe/63` and the probe worktree.
