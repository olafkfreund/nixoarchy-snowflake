# Spec: CI for nixoarchy-snowflake

## What the probe measured

A throwaway workflow on branch `ci-probe/63` (never merged) ran on `ubuntu-latest` (Ubuntu 24.04, 4 vCPU). Runs
`43467313124` and `43467852503` checked the sandbox, a fit test and the build, and `43568839355` ran the whole suite:

- **The sandbox tests can run.** Ubuntu sets `kernel.apparmor_restrict_unprivileged_userns = 1`, which blocks `bwrap`.
  After `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`, one more thing failed: the sandbox binds only
  `/nix/store`, and a plugin's `#!/usr/bin/env` line needs an `env` there. Bind-mounting Nix coreutils' `env` over
  `/usr/bin/env` (as on NixOS) fixed it: `test_plugin_sandbox.py` ran 37 tests, 0 skipped, in 6 s.
- **Setup is cheap:**
  - checkout and Nix install: 4 s
  - the sysctl and the bind mount: 21 s
  - `nix build .#default` cold: 21 s (run `43467852503`)
  - `nix flake check`: 33 s on p620
- **The whole suite, file by file, serially: 43 min.** It splits like this:

  | Group | Files | Time |
  | --- | --- | --- |
  | Unit tests (not `*_fit`) | 73 | 153 s |
  | Browser fit tests, except the two below | 14 | 698 s |
  | `test_character_fit` + `test_accessories_fit` | 2 | 1008 s + 719 s |

- **83 of 89 files passed.** The other six:

  | File | Cause | Decision |
  | --- | --- | --- |
  | `test_sessions.py` | `test_send_needs_an_exact_match` (`:143`) doesn't mock `herdr_read`: on p620 it reads a **live herdr pane**; the runner has none | Fix the test (it leaks to the live system) |
  | `test_mail.py` | 6 Hear test methods (8 errors with subtests) need `Speaker.available()` (`app/server.py:6784`), which checks the host's audio | Fix the fixture |
  | `test_mirror_fit.py` | "idle shrinks after off" waits a fixed 1.5 s (`tests/mirror_fit.mjs:35`); too short on the runner | Fix: wait for the condition |
  | `test_character_fit.py` | "plug:fixture: skin halo fits 340 × 460": a real 0.08 px overflow with DejaVu fonts | Design section 6 |
  | `test_bridge.py` | 4 skips: no `NIXI_SRC` | Allowed skip |
  | `test_window_webkit.py` | 1 skip: no Wayland | Allowed skip |

## Design

### 1. `.github/ci/run_tests.py`: the runner (new, about 140 lines)

A prototype exists on the probe branch, with its own test passing (section 7).

```bash
python3 -B .github/ci/run_tests.py [--deadline S] [--allow FILE] [--exclude NAME]... [--tests DIR] [PATTERN...]
```

- **One process per file:** for each `tests/test_*.py` it starts itself as a child (`--child DIR FILE REPORT`). The
  child runs `unittest` discovery for that one file (`top_level_dir` = the tests folder, `verbosity=2`).
  - **Discovery, not `python3 tests/x.py`:** seven files (`test_agent_approvals.py` and others) have no
    `unittest.main()`, so running them directly runs nothing.
  - Each file is imported as a top-level module with `tests/` on `sys.path`, which is how each file is run today.
- **The report:** the child writes `{"run": testsRun, "skipped": [[id, reason], ...]}` to a file in a private
  `TemporaryDirectory`, removed after each file. It does not parse the text output: reasons can be quoted either way,
  and tests print on the same line.
- **The verdict per file:**

  | State | When |
  | --- | --- |
  | `TIMEOUT` | the deadline passed |
  | `FAIL` | the exit code isn't 0 |
  | `NOREPORT` | no valid report, for example an `os._exit(0)` at import |
  | `EMPTY` | no tests run and no skips |
  | `SKIP?` | a skip not in the allow-list |
  | `ok` | otherwise |

  Every state except `ok` fails the job. A class or module skip (`setUpClass` raising `SkipTest`) counts as a skip,
  not as `EMPTY`.
- **Deadline:** 300 s per file by default, and `--deadline` sets it for every file in the call. There are no
  per-file values hidden in the code.
- **Cleanup, so nothing outlives a file:**
  - The output goes to a **file, not a pipe**, so a leftover child that holds it can't stall the runner.
  - After the child exits, or at the deadline, the runner kills the child's process group.
  - The runner is a child subreaper (`prctl(PR_SET_CHILD_SUBREAPER)`). Descendants that started their own session
    (`start_new_session`, `bwrap --new-session`) are re-parented to it, and it kills them until none is left.
- **Each file gets a fresh `HOME` and `XDG_RUNTIME_DIR`** (temporary, `0700`, removed afterwards). The runner's own
  HOME is never reached, on top of what `tests/nixi_env.py` already does in each test.
- **Patterns:** each one must match at least one file, or the run stops, so a renamed file can't drop out silently.
  `--exclude NAME` (repeatable) leaves a file out, so the two jobs split the suite.
- **Output:** one line per file: the state, the seconds, the tests run and the skip count. Then one line per skip, with
  its id (`file::Class.test`), its reason, and whether it is `allowed`. The full output of every file that isn't `ok`
  goes in a collapsed `::group::`, and a last line counts the files that passed.

### 2. `.github/ci/skips.txt`: the allow-list (new)

One entry per line, `file::<test id without the module>  # reason`. An entry without a reason stops the run.

```text
test_bridge.py::BridgeTest.test_1_text_streams_as_delta  # needs the nixi-nixarchy bridge checkout (NIXI_SRC)
test_bridge.py::BridgeTest.test_2_permission_yes_sends_allow_once  # needs NIXI_SRC, as above
test_bridge.py::BridgeTest.test_3_stop_proc_cancels_turn  # needs NIXI_SRC, as above
test_bridge.py::BridgeTest.test_4_dead_bridge_restarts_on_next_prompt  # needs NIXI_SRC, as above
test_window_webkit.py::WebKitTokenScript.test_right_port_only  # needs a Wayland session; GitHub runners have none
```

The other skip sources the intent lists are provided instead:

- **Chromium, Node, ffmpeg** from the locked flake (section 3)
- **`origin/main` for the character baseline:** `fetch-depth: 0`
- **`NIXI_DOCS_ALL=1`:** a missing doc fails

### 3. `flake.nix`: a `ci` dev shell

`devShells.<system>.ci` = the default shell's packages plus `chromium`, `nodejs` and `ffmpeg`, with
`NIXI_SANDBOX_TESTS = "require"` and `NIXI_DOCS_ALL = "1"`. Everything comes from the flake's locked nixpkgs, never
`nixpkgs#…` from the registry. That includes the `env` for the bind mount:
`nix develop .#ci -c sh -c 'command -v env'`. The default shell stays small for local sandbox runs.

### 4. `.github/workflows/ci.yml` (new)

- **Triggers:** `push` to `main`, `pull_request`, `workflow_dispatch`.
- `permissions: contents: read`. No secrets are used.
- **Concurrency:** `group: ci-${{ github.event.pull_request.number || github.sha }}`, with `cancel-in-progress: true`.
  A newer push to a PR cancels the older run, and two pushes to `main` never cancel each other.
- **Actions pinned by full commit**, the same pins as nixi-nixarchy's CI:
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1), with `fetch-depth: 0` and
    `persist-credentials: false`
  - `cachix/install-nix-action@526118121621777ccd86f79b04685a9319637641` (v31.3.0)
- **Setup, shared by both jobs:** checkout, Nix, then one step:

  ```bash
  # GitHub runner only: let bwrap make user namespaces, and give the sandbox a Nix env, as on NixOS.
  sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
  sudo mount --bind "$(nix develop .#ci -c sh -c 'command -v env')" /usr/bin/env
  git rev-parse --verify origin/main   # the character baseline needs it; fail here, not as a skip later
  ```

- **Two jobs on `ubuntu-latest`, side by side** (open question 1):
  - **`test`** (`timeout-minutes: 40`), expected about 16 min:
    1. setup
    2. `nix build -L .#packages.x86_64-linux.default`: `nix flake check` only evaluates packages, so the build needs
       its own step
    3. `nix flake check -L`: the `checks` (`wrapper-has-sandbox-tools` and the rest)
    4. `nix develop .#ci -c python3 -B .github/ci/run_tests.py --exclude test_character_fit.py --exclude
       test_accessories_fit.py`
  - **`fit-slow`** (`timeout-minutes: 75`), expected about 30 min:
    1. setup, without the build and the checks
    2. `nix develop .#ci -c python3 -B .github/ci/run_tests.py --deadline 1800 test_character_fit.py
       test_accessories_fit.py`

    Two 1800 s deadlines plus setup fit in 75 min, so even a double timeout is reported by the runner, not cut off by
    GitHub.

### 5. Test fixes the probe found

- `tests/test_sessions.py:139-143`: patch `s.herdr_read` to return a fixed pane text, so the test checks what it means
  to and never reads a live herdr pane.
- `tests/test_mail.py`: `MailBoardTest.setUp` (`:73`) patches `s.Speaker.available` to return `True` for every test.
  This fixes the 6 failing Hear methods:
  - `test_hear_gets_readonly_and_speaks_clean_local_summary`
  - `test_hear_registers_the_sid_with_the_gen_it_checked`
  - `test_html_get_and_long_model_answer_are_sanitized`
  - `test_model_failure_returns_subject_and_speaks_fixed_line`
  - `test_otp_from_message_scrubs_model_output`
  - `test_subject_otp_and_body_secrets_are_kept_out_of_the_prompt`

  It also makes the "never speaks" tests meaningful on a host without audio: a broken lock or sender guard can't hide
  behind `available()` being `False`. The two tests that set `available` themselves (`:798`, `:807`) keep their own
  patch.
- `tests/mirror_fit.mjs:35-36`: the check that idle shrinks waits a fixed `MS(..., 1500)`. It becomes: run `MS(...)`,
  so `__mir` and `mirSet` still happen, then poll every 100 ms for up to 6 s until `peek` is set. The waits at
  `:38-40` stay: they check that something does *not* happen, which polling can't prove faster, and they passed on the
  runner.

### 6. `test_character_fit`'s halo check

**Measured:** the same case, with bounds printed to two decimals:

| Where | Fonts (`fc-match sans-serif`) | Halo bounds | Weather "rain" bounds |
| --- | --- | --- | --- |
| p620 | Noto Sans | `8.47,3.45,331.74,326.41`, passes | `102.70,5.96,235.82,94.82` |
| runner, run `43573982762` | DejaVu Sans | `9.73,2.92,331.51,325.45`, top 0.08 px past the 3 px margin | `102.70,5.96,235.82,94.82` |

With Chromium's CPU slowed 4× on p620, the case still passes, so slowness isn't the cause. The page geometry is the
same on both machines (the weather boxes match to 0.01 px), and only the halo moves with the font. So it is a **real
overflow** for anyone whose default sans font is DejaVu, a common default. The test caught it correctly.

**Decision:** a new issue, "plugin character halo overflows its margin with DejaVu fonts". It is fixed in the app, on
its own branch, before the CI PR merges, so CI starts green. The bound isn't loosened, and CI doesn't switch fonts to
hide it. Until that fix lands, the CI PR's `fit-slow` job is red on exactly this one check.

### 7. `tests/test_ci_runner.py`: the runner's own test (new)

It builds a temporary tests folder and runs the runner on it. The expected states:

| File | Expected |
| --- | --- |
| passing | `ok` |
| failing | `FAIL` |
| skip not on the list | `SKIP?` |
| skip on the list | `ok` |
| `setUpClass` skip on the list | `ok` |
| no tests | `EMPTY` |
| `os._exit(0)` at import | `NOREPORT` |
| a test that sleeps past a 4 s deadline, after starting an orphan in its own session | `TIMEOUT`, and the orphan is gone |
| a test that checks its `HOME` differs from the caller's | `ok` |

It also checks:

- only passing files exit 0
- `--exclude` works
- a pattern that matches nothing stops the run
- an allow-list line without a reason is refused

It runs in about 7 s.

## Alternatives rejected

- **The whole suite in one job:** 43 min per PR.
- **The two slow fit tests only on `main`:** PRs that change the character would merge before the check runs.
- **Running files in parallel in one job:** the fit tests are timing-sensitive (`test_mirror_fit` already failed
  serially on the runner), and 4 vCPUs shared with Chromium would make that worse.
- **`nixpkgs#…` from the registry:** unpinned, so a run could change with no change in the repo.
- **Ubuntu's Python or Chromium:** the sandbox runs `sys.executable` inside a `/nix/store`-only bind, and Ubuntu's
  `chromium-browser` is a Snap that won't start with `HOME` redirected.
- **Checking out nixi-nixarchy for `test_bridge`:** a second repo and `npm ci`, for tests that are allowed to skip.
- **A self-hosted runner** for user namespaces: not needed, since the sysctl works.
- **`magic-nix-cache`:** the setup takes under 30 s; a cache adds an action for little.
- **Parsing `unittest`'s text output for skips:** tried in the probe, and it missed reasons in double quotes.

## Risks

- **GitHub changes the runner image** (the sysctl name or the AppArmor policy): the setup step or the sandbox tests
  fail loudly, because they run in require mode. They never skip silently.
- **Timing flakes in the fit tests** on a slow runner. The deadlines leave room (300 s against at most 168 s measured
  outside the slow pair). A flaky check gets fixed in the test, by waiting for a condition, never by a retry loop.
- **The sandbox sees more tools in CI than in the package:** `sandbox_argv` copies the `/nix/store` entries of `PATH`
  (`app/plugins.py:655`), so inside `.#ci` a plugin could find `node` or `ffmpeg`. A test that passes only because of
  them would pass in CI and fail for users. `wrapper-has-sandbox-tools` keeps checking the package's own `PATH`.
- **`/etc/ssl` on Ubuntu:** the sandbox binds it for network plugins. There, the bundle is a regular file, but the
  per-hash links point outside the bind. The sandbox tests passed with it, and no test relies on the hash links.
- **Free minutes:** both jobs, about 46 runner-minutes per run, are free while the repo is public.
- **No host of ours is touched:** the sysctl and the bind mount happen on GitHub's throwaway runner. Branch protection
  stays the owner's choice.
