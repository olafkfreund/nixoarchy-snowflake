# Intent: accept an ElevenLabs key from sops-nix

## Problem

Nixi reads the ElevenLabs API key from a file, `eleven_key_file`, by default `/run/agenix/api-elevenlabs`. `_key()` in
`app/eleven.py:36-56` resolves the path with `realpath`. It then accepts it only under these roots:

- `/run/agenix`
- `/run/agenix.d`
- `/run/secrets`
- `$CREDENTIALS_DIRECTORY`

sops-nix puts a secret at `/run/secrets/<name>`, which is a symlink to `/run/secrets.d/<generation>/<name>`. After
`realpath` the key is under `/run/secrets.d`, so Nixi refuses it, and only agenix works. `docs/GUIDE.md:327` says so:
"sops-nix is not supported yet".

## Proposed outcome

- A key provided by sops-nix (`/run/secrets/<name>` resolving into `/run/secrets.d/<gen>/<name>`) is accepted, and
  Nixi speaks with ElevenLabs.
- `docs/GUIDE.md` shows the sops-nix setup next to the agenix one, and no longer says it is unsupported.

## Affected users and systems

- `app/eleven.py` (`_key`), `docs/GUIDE.md` (the key section, about lines 305-330), `tests/test_eleven.py`.
- Anyone who keeps the ElevenLabs key in sops-nix. agenix users see no change.

## Constraints

- **Every other check stays as it is:**
  - a no-follow open of the resolved path
  - a regular file
  - owned by root or the user
  - 1 to 256 bytes
  - the key format
  - the key never appears in an error
- **Only sops-nix's own runtime root is added.** No broader pattern: no `/run` as a whole, and no `/nix/store`, which
  is world-readable.
- `tests/test_docs_names.py` (#217) must still pass after the GUIDE edit.
