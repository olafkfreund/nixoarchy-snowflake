# Intent: a skill for making and sharing Nixi plugins

## Problem

Nixi has a plugin format and local packaging, but no guided route from an
idea to a working, checked, shareable plugin. The owner and other users
have to piece it together from the source code.

- **The rules live in code, and the guide covers only part of them.**
  - The manifest keys are in `app/plugins.py:28–38`: required and optional
    keys, prop, character and stage keys, and categories. The reactions are
    at `:111`.
  - They are enforced in `_check` (`:114–232`), which covers these rules:
    - a network plugin cannot read status (`:219–224`);
    - `argv[0]` must be inside the folder (`:225–226`);
    - no absolute or `..` arguments (`:227–228`);
    - no phrase may clash with a reserved one (`:229–231`);
    - `videos` is for `news` only (`:203–204`).
  - Other enforced rules: an SVG sanitiser (`:462–578`), no symlinks, and a
    `--check` that rejects private characters (`:1036–1037`).
  - The guide's plugin section (`docs/GUIDE.md:460–508`, option at `:522`)
    and `docs/GETTING-STARTED.md:127–145` explain the format. They do not
    cover most of the rules above, and the guide omits `reactions`.
- **The starting points are incomplete.**
  - The six folders in `plugins/examples/` each show one feature. None
    shows a `character` or `reactions`.
  - `news` uses `videos`, which no other plugin may use.
  - There is no template.
- **No walkthrough for sharing.**
  - The tools exist: `lib.<system>.mkCompanionPlugin` (`flake.nix:31–34`)
    builds a checked plugin, `services.nixi.companion.plugins` installs one,
    and `plugins.py --check` validates one. The guide also shows how to
    package a local folder.
  - Nothing says "put your plugin in its own repo with a flake output, and
    others add it as an input".
- **No skill.** Claude Code here has a `nixi` skill for beginner how-to
  questions, and none for authoring Nixi plugins. `omarchy-make-plugin` is
  for Omarchy, not Nixi.

## Proposed outcome

- **A `nixi-plugin` skill.** It takes a person, or Claude Code helping them,
  through these steps:
  1. **Choose the kind:** quips, prop, character, notifications, reactions
     or a stage program.
  2. **Start from a template,** and fill in `plugin.json` within the rules
     above, including what each `reads` feed contains. For example,
     `phone-status` gives only device name, online, battery and charging,
     and only while Phone is on.
  3. **Check it:** run `plugins.py --check`, then a real run. Install it as
     a folder plugin, accept the consent prompt, and see its card. The
     sandbox needs `bwrap`, plus `pasta` for network plugins.
  4. **Install it:** as a folder plugin, or through
     `services.nixi.companion.plugins`.
  5. **Publish it:** in its own repo with a flake output built with
     `mkCompanionPlugin`. Others add it as a flake input.
- **Private characters are a separate, local-only path.** No repo, no Nix
  and no `--check`, which rejects them by design. Owner-only permissions
  (`chmod -R go=`), as `docs/GUIDE.md:492–495` says.
- **A copyable template inside the skill**, outside `plugins/`, so Nixi
  does not load it as a plugin from a checkout. It contains a manifest,
  README, LICENSE and a minimal executable stage `run` that prints valid
  output. It passes `--check`, builds with `mkCompanionPlugin`, and runs
  once in the sandbox.
- **A test catches the worst drift.** It fails if the skill or the template
  names a manifest key, `reads` value, category or reaction that
  `plugins.py` does not accept. It cannot prove the skill mentions every
  new feature. That stays a review item.
- **Available to everyone who clones the repo.** `docs/GUIDE.md` links to
  the skill.

## Affected users and systems

- **This repo:**
  - `skills/nixi-plugin/`: `SKILL.md`, references and `template/`;
  - a test;
  - `docs/GUIDE.md` and `README.md`.
  - No change to `app/plugins.py` or to runtime behaviour.
- **nixos_config** (only if Open question 4 says so): a link from the skill
  into `~/.claude/skills` on p620 and razer.
- **Other Nixi users:** they gain a guide.

## Constraints

- **Today's plugin API (`api: 1`) only.** No new capabilities. WhatsApp is
  separate work, in #126.
- **The skill never suggests anything the sandbox or checker forbids:**
  - `network` together with `reads`;
  - paths or arguments outside the folder;
  - symlinks or hard links;
  - `videos`;
  - skipping the SVG limits;
  - committing a private character.
- **The template stays outside the folders Nixi scans** (`app/plugins.py`
  lines 63–65 and 320–321).
- **Licence.** The template copies example material under its MIT licence
  and keeps the notice.
- **Skill format.** Follow the format used under `~/.claude/skills`:
  frontmatter with `name` and `description`.
- **p510 is not changed.** Agents never commit, push or deploy.
