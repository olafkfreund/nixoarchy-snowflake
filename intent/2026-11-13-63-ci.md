# Intent: CI for nixoarchy-snowflake

## Problem

nixoarchy-snowflake has no `.github/workflows/`. A PR shows no checks, so nothing stops a change that breaks the
tests, the plugin sandbox or the Nix build.

This session showed the cost. Two regressions reached the #231 branch and were found only by a manual per-file run:
- `test_mail` broke when a capture message changed
- `test_stage_actions` broke on a plugin without a stage

The plugin sandbox tests skip silently without `pasta` and still print `OK`, so a local run can look green while
testing nothing (README "Working on it"). The one-process suite run took over 25 minutes here; a run file by file
finishes. nixi-nixarchy already has CI (`nix flake check`, bridge tests, lint), but this repo has none.

## Proposed outcome

Every PR and push to `main` runs, and shows as checks:

- **The Python test suite** in `tests/`, each `test_*.py` in its own process:
  - with its own deadline, so a hang can't stall the job
  - with its child processes cleaned up
  - with a timed-out file counted as a **failure**, never a skip

  The `*_fit.py` files also match `test_*.py`, so each runs once.
- **The plugin sandbox tests** in require mode, through a Nix-provided interpreter and tools:
  - The sandbox binds `/nix/store` and runs `sys.executable` inside it (`app/plugins.py:654`), so Ubuntu's own
    Python can't work there.
  - The dev shell (`flake.nix:58`) supplies Python, `bwrap`, `passt` and `iproute2`, and sets require mode.
  - The tests **fail**, never skip, if the runner can't run them.
- **The package build:** `nix build`, plus the repo's `checks` (`wrapper-has-sandbox-tools` and the others in
  `flake.nix`).
- **The browser fit tests** (`*_fit.py`, headless Chromium with `--disable-gpu`). They run where the runner allows,
  and are skipped with a stated reason where it doesn't.

## Affected users and systems

- A new `.github/workflows/ci.yml`, plus possibly small test tweaks so the suite runs headless on a GitHub runner.
- PR authors and agents: PRs here get checks. Branch protection, making the checks required, is a separate choice for
  the owner.
- No host or deploy is affected.

## Constraints

- **Tests never touch a real HOME, runtime dir, voice or window** (`tests/nixi_env.py`, #176). On a runner that is
  natural, but the workflow must not weaken it.
- **Actions are pinned by commit,** like nixi-nixarchy's CI. No secrets: the ElevenLabs and agent tests use fakes.
- **Known environment failures get an explicit skip with a reason, never a silent pass.**
  - **Never for the sandbox tests:** they guard the plugin security boundary. If the hosted runner can't run `bwrap`
    under Ubuntu's user-namespace restriction, the spec has to find a way to run them, not skip them.
  - Browser fit tests that can't start Chromium may be skipped, with a stated reason.
  - `test_accessories_fit` and `test_character_fit` already time out on p620; the spec decides, after measuring,
    whether they get a longer deadline or a stated skip.
- **Skips are visible and explicit.** `unittest` exits 0 on a skip, so a green check could hide untested code.
  - The workflow reports each file's skip count.
  - It fails on any skip that isn't on a short, reviewed allow-list, each entry with its reason.
  - Known skip sources today (agy review): `test_bridge` without `NIXI_SRC`, `test_window_webkit` without Wayland and
    WebKit, the `test_character_fit` baseline without `origin/main` (CI checks out shallow), `test_docs_names` without
    `NIXI_DOCS_ALL=1`, and the mp3 decode test without `ffmpeg`. The spec decides, per entry, whether to provide the
    missing piece or allow the skip.
- **Tools come from Nix,** not the runner image. Ubuntu 24.04's `chromium-browser` is a Snap wrapper that won't start
  with `HOME` redirected, as the tests do, so Chromium, Node and the other tools come from Nix.
- **Keep it cheap:** one Linux runner by default, and only `x86_64-linux` for `nix build`. The package pulls in
  WebKitGTK and speech libraries, so the spec measures a cold-cache run before promising a time.

## Open questions

- Can a GitHub-hosted runner allow the user namespaces `bwrap` needs? That is decided by a trial run in the spec.
  The tests must run, so the options are, for example, relaxing the AppArmor restriction on the runner, or a
  different runner.
- Should the checks become required in branch protection? It is the owner's choice. This draft only adds them.
