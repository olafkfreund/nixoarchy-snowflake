# Intent: CI for nixoarchy-snowflake

## Problem

nixoarchy-snowflake has no `.github/workflows/`. A PR shows no checks, so nothing stops a change that breaks the
tests, the plugin sandbox or the Nix build.

This session showed the cost. Two regressions reached the #231 branch and were found only by a manual per-file run:
- `test_mail` broke when a capture message changed
- `test_stage_actions` broke on a plugin without a stage

The plugin sandbox tests skip silently without `pasta` and still print `OK`, so a local run can look green while
testing nothing (README "Working on it"). The one-process suite run took over 25 minutes here; a run file by file
finishes. nixi-nixarchy already has CI (`nix flake check`, bridge tests, lint), but this repo has none.

## Proposed outcome

Every PR and push to `main` runs, and shows as checks:

- **The Python test suite** in `tests/`, each `test_*.py` in its own process, so one slow or hanging file doesn't
  sink the run.
- **The plugin sandbox tests** in require mode, failing rather than skipping when `bwrap` or `pasta` can't run.
- **The package build:** `nix build`, plus the repo's `checks` (`wrapper-has-sandbox-tools` and the others in
  `flake.nix`).
- **The browser fit tests** (`*_fit.py`, headless Chromium with `--disable-gpu`). They run where the runner allows,
  and are skipped with a stated reason where it doesn't.

## Affected users and systems

- A new `.github/workflows/ci.yml`, plus possibly small test tweaks so the suite runs headless on a GitHub runner.
- PR authors and agents: PRs here get checks. Branch protection, making the checks required, is a separate choice for
  the owner.
- No host or deploy is affected.

## Constraints

- **Tests never touch a real HOME, runtime dir, voice or window** (`tests/nixi_env.py`, #176). On a runner that is
  natural, but the workflow must not weaken it.
- **Actions are pinned by commit,** like nixi-nixarchy's CI. No secrets: the ElevenLabs and agent tests use fakes.
- **Known environment failures get an explicit skip with a reason, never a silent pass.** Two examples:
  - Ubuntu's unprivileged user-namespace restriction for `bwrap`
  - `test_accessories_fit` and `test_character_fit`, which time out on p620 as well
- Keep it cheap: one Linux runner by default, and only `x86_64-linux` for `nix build`.

## Open questions

- Should the sandbox tests run inside `nix develop` (they need `bwrap`, `passt` and `iproute2` from the dev shell),
  and can a GitHub runner allow the user namespaces `bwrap` needs? The spec decides, after a trial run.
- Should the checks become required in branch protection? It is the owner's choice. This draft only adds them.
